## 1. 好吧，我自己造个文本编辑器

- 原始链接: <https://dbushell.com/2026/09/01/text-editor/>
- 英文标题: Fine, I’ll build my own text editor

作者因不满当下软件质量，决定从零构建一个文本编辑器，并依次尝试了三种渲染方案。第一种是 Canvas 方案：在 <canvas> 上以 60–120fps 渲染文本，实现了光标定位、箭头移动、当前行高亮、输入和光标动画等最小功能集，但缺乏文本选择、撤销/重做、多行粘贴和溢出滚动等关键能力，且完全不可访问，作者遂放弃。第二种是 contenteditable 方案：利用 contenteditable="plaintext-only" 让浏览器原生提供文本选择、撤销历史和 Selection API，大幅降低开发成本，但长文本下 Chromium 性能不稳定。第三种是 Textarea 方案：对长文本性能远优于前两者，作者在此基础上叠加了 MicroLighter 语法高亮层，效果接近可用。文章还提及 OpaqueRange API 可为 textarea 解锁自定义高亮、EditContext API 改善 Canvas 输入等新进展，并建议用 Tree-sitter 生成语法树配合虚拟滚动来优化高亮性能。最终作者认为当前 demo 已具备编辑器约 90% 的外观但仅 1% 的功能，决定暂搁项目。文末以 UTF-16 编码下 emoji 长度计算的陷阱（「🍋‍🟩」.length 为 5 而非 1）作为彩蛋，提醒开发者注意字符串处理的坑。

## 2. 造一个新词「zuzai」，标记AI的缺席

- 原始链接: <https://zuzai.org/>
- 英文标题: Zuzai, a new word, indicates the absence of AI

作者提议造一个新词「zuzai」（递归缩写，意为「zuzai uses zero artificial intelligence」，发音近似「zoo's eye」），用以标记某物完全未使用AI工具。文章指出，AI生成内容已大量侵入人们不愿其出现的领域，但英语中缺乏一个简洁、正面、不以AI为中心的词来描述「非AI」状态；现有表达如「AI-free」「human-generated」等要么冗长，要么以AI为参照，不够理想。作者逐一排除了「human」「traditional」「hand-made」「artisanal」「analog」「natural」等候选词，说明它们各有局限；也考察了日、俄、中等多种语言，未发现完美对应词。作者认为zuzai虽属新造词，但可类比1944年诞生的「vegan」，有望成为积极、轻快的标签，适用于作品、流程乃至环境等多种语境。文章还讨论了该词是否属于「回溯词」（retronym）、如何认证某物确实「zuzai」（提及C2PA标准）等问题，并坦承广泛采纳仍是长路。全文本身及配图均为zuzai作品。

## 3. CSS 压缩（Minify）是否还有必要？（2023）

- 原始链接: <https://shivjm.blog/is-minifying-css-necessary/>
- 英文标题: Is Minifying CSS Necessary? (2023)

本文作者 Shawn 明确反对在构建流程中加入 CSS 压缩（即去除空白与注释）步骤，并通过实测数据论证其收益微乎其微。在文件大小方面，以 Bootstrap 为例，仅做 gzip 即可从 147 KB 降至 22 KB，再叠加 minify 仅再省 2 KB，相比同页 38 KB 的压缩 HTML 和 1.8 MB 的总资源量完全可以忽略。在解析性能方面，作者自建测试工具，在桌面与手机上分别测试 1 万、10 万、1 千条声明块的样式表：1 万块解析耗时 9–10 ms，10 万块 95–105 ms，1 千块则快至无法测出差异。随后他按社区建议改用 WebPageTest 在低配设备与慢速网络下复测，最坏情况（1 千块）压缩与未压缩的渲染起始时间差仅 54 ms，10 万块时差距更小。作者还从工程文化角度指出，90 年代末学 CSS 时查看源码是重要途径，minify 只会让代码变得难以阅读，而现代浏览器开发者工具已能很好地格式化展示。最终结论：除非你是对每毫秒都精打细算的超大型公司且样式表信噪比极低，否则 gzip 或 Brotli 已完全足够，无需额外增加 minify 环节。

## 4. 谓词逻辑速成课

- 原始链接: <https://www.hillelwayne.com/post/predicate-logic/>
- 英文标题: A Crash Course in Predicate Logic

本文是《面向程序员的逻辑》一书第二章的免费博客版，系统介绍谓词逻辑的基本概念与语法。首先，谓词是返回布尔值的数学概念，与编程函数不同，它只定义答案而非给出计算方式，因此可表达尚不可计算的事物；作者用反引号区分抽象谓词与具体谓词，并约定谓词用大驼峰、普通函数用蛇形命名。接着，文章以「程序能否运行」的需求为例，展示自然语言中「A且B或C」的括号歧义，通过真值表明确两种解读的差异，强调形式化表达优于自然语言。随后引入蕴含运算符「=>」（等价于「!P || Q」），用于表达条件约束，并指出其传递性，例如「在某输入下崩溃」蕴含「存在缺陷」。之后引入集合为谓词参数提供类型约束，介绍并、交、差、子集等集合运算及集合推导式（map/filter 语法），并指出集合推导式是理解数据库查询的基础。最后引入量词：存在量词 some 表达「至少一个元素满足」，全称量词 all 表达「所有元素满足」，以代码审查合并规则为贯穿示例。文章在 all 量词部分截断。

Wasmi 2.0 是一款高效的 WebAssembly 解释器，经八个月开发正式发布，在 Apple M2 Pro 上执行性能较 1.0 提升约 2.2 倍（几何平均），在 wasmi-benchmarks 套件中跻身最快可移植 Wasm 解释器行列。文章系统阐述了三大核心技术：其一，引入四种指令分发模式——直接线程码（最快）、间接线程码（兼顾内存）、开关循环（兼容不支持尾调用的平台）和调用循环，并默认启用自动分发；其二，以三个累加器寄存器（ireg、freg32、freg64）替代 1.0 中频繁的栈槽读写，将中间结果直接保存在硬件寄存器中，显著减少解码与内存访问开销，并辅以操作码融合和专用复制指令缓解由此带来的额外拷贝；其三，将实例对象从 1.0 的多次堆查找改为连续内存布局，使对象访问仅需一次指针偏移。此外，2.0 新增 validate 特性以缩减二进制体积、稳定燃料计量、支持 Wasm 确定性 profile 及改进 CLI 工具。文章还对比了 Wasm3、WAMR、Wasmtime Pulley、Stitch 等竞品，并讨论了 sysv64 调用约定下 GPR 数量不足等工程细节。

## 11. 类型类的一致性约束与孤儿实例规则

- 原始链接: <https://osa1.net/posts/2026-08-29-coherence-and-orphans.html>
- 英文标题: Coherence and orphan instance rules

本文围绕类型类（typeclass）机制中的「一致性」（coherence）与「孤儿实例规则」（orphan instance rules）展开讨论。作者首先说明类型类通过类型参数在编译期或运行期将方法调用解析到具体实例，当类型参数未出现在方法签名中时需显式标注。核心概念「一致性」要求：对同一约束，整个程序中至多匹配一个实例，从而保证同一调用在任意位置解析到相同方法。作者列举了打印格式统一、序列化/反序列化兼容、哈希与有序结构不变量等典型依赖场景，并强调一致性是全局（全程序）属性——即使各模块单独一致，组合后仍可能因重叠实例而破坏一致性。为解决库的可组合性问题，孤儿实例规则限制实例只能定义在类型或类所在模块，防止第三方模块引入冲突实例。作者以 Rust 的「Re-rebalancing coherence」RFC 为例，指出该规则是前一次更严格规则的修订版，且其正确性（即允许两库各自定义实例后第三方组合仍一致）并不显然。最后，作者指出目前学界缺乏对孤儿实例规则的正式化证明——即证明规则仅允许全局一致系统且覆盖常见用例——并认为这是编程语言设计领域的一个开放研究方向。

## 13. 让 CSS random() 函数在所有浏览器中可用：一个 Polyfill 实践

- 原始链接: <https://css-tricks.com/css-random-function-polyfill/>
- 英文标题: Let’s Use the Emergent CSS random() Function in all the Browsers

文章从「随机性」这一设计主题切入，介绍 2025 年底 Safari 率先支持的 CSS random() 函数——它允许在样式层直接生成随机值，无需 JavaScript。然而 Chrome 和 Firefox 尚无明确支持时间表，作者（一位 CSS 顾问）遂开源了 css-random-polyfill 包，将该函数移植到所有浏览器。Polyfill 要求将 random() 调用存入以「--random」为前缀的自定义属性，并在元素上添加「randomized」标记类，页面加载时由脚本解析。文章通过四个演示展示语法覆盖：随机星空（含 step 间隔与 element-shared 共享值）、随机彩色网格（random() 嵌套于 grid-area 简写）、幸运轮盘（混合 turn 与 deg 单位）、随机方块（通过自定义键共享宽高值）。此外，作者利用 Chromium 已支持的 CSS 自定义函数与内联条件表达式，模拟了尚未实现的 random-item() 函数，实现从任意列表中随机选取。Polyfill 底层基于 MIT 协议的 @csstools/css-calc 包（原为 PostCSS 构建时插件），移植到客户端代码量不大。作者坦言对 polyfill 内部机制尚未完全掌握，但强调其设计目标是：一旦原生支持普及，删除脚本引用后代码仍可直接运行。
