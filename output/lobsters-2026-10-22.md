## 1. Firefox 本地模式（Local Mode）功能介绍

- 原始链接: <https://firefox-source-docs.mozilla.org/devtools-user/local_mode/index.html>
- 英文标题: Firefox Local Mode

本文介绍 Firefox 153 新增的「本地模式」功能。该功能允许用户在 DevTools 的 Options 面板中注册多条映射，将本地文件夹绑定到自定义的 https:// 地址（如 https://firefox.localhost），从而无需启动本地 HTTP 服务器即可在浏览器中测试网页。其核心优势包括：可测试所有 Web API，包括仅限安全上下文（Secure Contexts）使用的接口；为不同实验或项目分配独立 origin，使各自的存储与 cookies 互不干扰；映射仅对 Firefox 生效，其他程序或恶意软件无法访问；且仅在 DevTools 打开时有效，安全性较高。使用方式上，用户可在 Options 面板中逐条添加映射，每条映射需指定 origin（自定义域名）和本地文件夹路径。当通过 file:// 协议加载文件时，DevTools 顶部会弹出通知，提供「添加到设置」和「临时试用」两个操作：前者创建持久映射，后者为临时映射，关闭 DevTools 或 Firefox 后即失效。此外，映射也可通过 about:config 中的偏好设置进行管理，每条映射由三个键值定义：devtools.local-mode.mappings.${index}.origin（域名）、.path（本地绝对路径）、.disabled（可选布尔值，用于禁用该映射），其中 ${index} 为递增整数。这种方式便于在多个配置文件间导入、迁移映射，或用于自动化场景。

## 2. PHP 8.5.12 等版本紧急修复两个未授权远程代码执行漏洞

- 原始链接: <https://www.php.net/archive/2026.php#2026-10-20-1>
- 英文标题: Upcoming Critical PHP Security Release

PHP 安全团队发布紧急更新，PHP 8.5.12、8.4.27、8.3.36 和 8.2.35 修复了两个可导致未授权远程代码执行（RCE）的严重漏洞。CVE-2026-109618 源于内存溢出处理中断使请求数据仅部分初始化，清理阶段将无效数据误判为有效数据；CVE-2026-109619 源于请求内部状态在底层内存释放后仍残留，同一 worker 的后续请求可能在正常初始化前复用该过期状态。所有 PHP 安装均受影响，涵盖 PHP-FPM、mod_php、php-cgi、FrankenPHP 及 LiteSpeed，其中 mod_php 风险最高，已有演示表明未认证请求可在应用代码执行前触发攻击。PHP 8.1 及更早版本不再获得官方更新，但安全团队为 7.4、8.0、8.1 提供了最小源码回移补丁。若无法立即升级，可设置 memory_limit=-1、降低 post_max_size、禁用 session.upload_progress、在服务器层限制请求大小与嵌套深度等措施降低暴露面，但这些仅为临时缓解，唯一完整解决方案是更新至上述修复版本。

## 3. ZLS 0.17.0 发布说明

- 原始链接: <https://zigtools.org/zls/releases/0.17.0/>
- 英文标题: zls 0.17.0

ZLS（Zig 语言服务器）0.17.0 版本发布。主要功能改进：重命名符号时不再跟随别名，例如重命名 foo() 仅影响函数调用及其直接引用，而重命名 fn foo 仍会修改全部相关位置，引用功能保持不变。构建系统集成方面，Zig 0.17 开发周期中 maker 与 configurer 进程的分离曾破坏 ZLS 的关键构建集成能力，大部分功能已通过新的构建系统协议恢复，但仍有若干回归待后续版本修复。已知回归包括：build.zig 中 @import 的类型解析失效、仅通过 addModule 导出且无编译步骤的模块无法解析、Windows 上文件监视因协议缺陷不工作（ZLS 通过 LSP 文件保存事件部分规避）。新协议为编辑器集成单元测试、模糊测试、代码覆盖率及调试等能力奠定基础。本次发布提供 Windows、macOS、Linux 及 WASI 等多平台多架构构建产物，均经 minisign 签名，并感谢所有贡献者与赞助者。

## 5. CVE-2026-107891：musl libc regcomp 函数整数溢出漏洞

- 原始链接: <https://www.openwall.com/lists/oss-security/2026/10/21/18>
- 英文标题: CVE-2026-107891: musl libc: multiple integer overflow in regcomp, possibly leading to incorrect allocation sizes and out-of-bounds heap writes

2026年10月21日，musl libc维护者Rich Felker发布安全公告，披露CVE-2026-107891：musl libc的regcomp函数存在多处整数溢出缺陷。当传入的正则表达式在规模和复杂度上达到特定条件时，溢出会导致内存分配大小计算错误，进而可能引发堆越界写入。触发条件取决于正则表达式本身的复杂度，而非待匹配数据；应用需处理来自不可信源的正则表达式才可能受影响。影响方面，攻击者至少可造成可预测的拒绝服务崩溃；在特定堆布局与并发执行条件下，存在任意代码执行的可能。该漏洞自0.5.0版本起存在，所有后续版本至1.2.6均受影响。修复方案为应用官方补丁或升级至1.2.7；若无法打补丁，应避免处理不可信来源的正则表达式。该漏洞由Julien Voisin首次私下报告，随后Szabolcs Nagy与Rich Felker通过进一步分析发现了一组同类溢出模式。公告附带了名为「0001-regex-avoid-int-overflow-in-regcomp.patch」的补丁文件（5943字节），发布于Openwall oss-security邮件列表。

## 6. 通行密钥的证明陷阱：用户自主权的隐性侵蚀

- 原始链接: <https://mjtsai.com/blog/2026/10/15/passkeys-attestation-trap/>
- 英文标题: Passkeys Attestation Trap

Michael Tsai 在博客中警告，通行密钥（passkeys）虽在防钓鱼方面优于密码，但其 FIDO 标准中的「证明」（attestation）机制构成一个渐进式陷阱。与密码、独立认证器或物理安全密钥不同，passkey 用户无法完全掌控凭证的存储与迁移；网站可通过逐步要求「已证明」的 passkey，悄然剥夺用户选择权。作者以 X（原 Twitter）为例，设想平台可分批拒绝非证明型 passkey，使数年内用户遗忘自己曾有选择。Apple 目前不支持证明，但正与 W3C、FIDO 合作解决同步问题，暗示未来可能跟进。FIDO 联盟的 Ricky Mondello 反驳称，证明在消费级场景中是明确的非目标，浏览器和凭证管理器已统一立场拒绝。然而 Tsai 及多数评论者认为，一旦技术成熟，大公司仍有动力强制推行，以锁定生态、排挤独立凭证管理器。评论区分歧明显：一方视之为技术阴谋论，另一方援引 Google 对 Android 的管控历史，主张大公司获得权力后必然滥用。最终共识指向两条出路：加强反垄断监管，以及开发者转向 FLOSS 与无账号应用，减少对少数科技巨头的依赖。

## 7. 即时模式UI的渲染缓存：不必每帧重绘一切

- 原始链接: <https://blickeditor.com/blog/caching-an-immediate-mode-ui>
- 英文标题: Don't throw it all away: Caching an immediate-mode UI

即时模式UI常被批评每帧重建整个界面描述，造成重复计算。本文以Blick（一款密集时间线编辑应用）为例，展示如何在渲染端引入缓存：UI前端仍每帧重建，渲染器仅重绘输入发生变化的区域。核心方案是将窗口划分为瓦片，对影响每个瓦片的绘制命令（含顺序）计算哈希并与上一帧比较，匹配则保留已有像素。渲染器使用一种小型GPU渲染语言，命令涵盖解析形状、纹理形状、形状组（合并几何后统一描边）和alpha屏障（整体淡入淡出，避免重叠区透明度错误）。音频波形等特殊视觉通过独立effects pass渲染至atlas纹理，渲染器只需采样纹理。缓存验证基于命令哈希而非逐像素比较，并需纳入纹理内容与动画的失效逻辑。在M3 Pro MacBook Pro轻编辑测试中，启用缓存后CPU+GPU功耗降低约20%，整机功耗降低约14%，预计多约2.4小时续航；同时少绘制约94%瓦片、GPU绘制时间减少87%。代价包括binning与哈希的额外开销、大量半透明元素减少早期退出机会，以及瓦片列表的固定容量限制。

## 8. 流类型：线性类型系统的新视角

- 原始链接: <https://jaredforsyth.com/posts/papers-we-love-lens-on-linearity/>
- 英文标题: Flow Typing, A New Lens on Linearity

本文介绍Wilshaw与Hutton提出的「流类型」（Flow Typing）方案，旨在解决线性类型系统中长期存在的「线程化问题」。线性类型系统要求每个值恰好使用一次，其优势包括：强制资源释放（如数据库连接、文件句柄的显式关闭）、通过禁止多观察者实现纯度、以及类似Rust借用检查器的并发安全保证。然而，线性语义下所有可变操作都必须按值传递，导致每次修改都要将对象显式「穿线」进出各函数，代码极为繁琐。流类型的核心创新在于借助「透镜」（Lens）理论——一种对嵌套数据子集进行纯函数式操作的机制——在标准线性lambda演算中实现受控的状态变更，无需扩展核心语言语义。作者将透镜项用于在类型上下文中以纯函数方式「变异」局部状态，从而在保留线性系统简洁语义的同时，提供接近可变引用的使用体验。该方案语义简单、可直接在标准线性lambda演算中实现，甚至支持形式化正确性证明。作者正在将流类型的执行模型落地到一种新编程语言中，并分享了实践笔记，关注其实际编码体验与实现难度。文章由Papers We Love栏目发布，属于编程语言与编译器研究方向。

## 13. 用 CSS 媒体查询提升网站可访问性（2025）

- 原始链接: <https://fleeb.ee/blog/improving-accessibility-with-css-media-queries/>
- 英文标题: Improving accessibility with CSS media queries (2025)

文章指出可访问性常在设计后期才被顾及，而 CSS 媒体查询提供了一种无需推翻原有设计、即可响应用户偏好的改善途径。作者介绍了四种媒体查询：prefers-contrast 可为偏好高对比度的用户增强文本对比度，WCAG 2 建议小文本最低 4.5、大文本最低 3.0；prefers-reduced-motion 可针对偏好减少动效的用户禁用或降低动画，也可用通配符全局关闭，但需检查副作用；prefers-color-scheme 根据系统明暗模式切换配色，2024 年起可借助 color-scheme 与 light-dark() 函数简化实现，同时让浏览器自动适配滚动条等默认颜色；prefers-reduced-transparency 为实验性查询，可将半透明元素设为不透明，但 Firefox 与 Safari 尚不支持，建议保守使用。文章强调，可访问性偏好多为开关式设置，而用户实际障碍呈连续谱分布，因此应以合理可访问性为设计起点，这些媒体查询是灵活补充而非万能方案。

本文以 my_counters 应用为例，逐步演示如何将 EYG 脚本语言嵌入 Erlang 程序，构建一个受控的脚本执行环境。EYG 工具包由 eyg_parser、eyg_interpreter、eyg_analysis 等可组合组件构成。文章首先展示最简执行路径：用 eyg_parser 将字符串解析为源码，再由 eyg_interpreter 求值，即可运行无副作用的纯 EYG 程序（如 !int_add(2,1) 返回 3）。随后加入错误美化输出，利用各包自带的 format_error、inspect、render_error 等函数，将解析错误和运行时错误格式化为可读文本，并扩展 run/1 以同时接受 charlist 和 binary 输入。核心环节是引入代数效应（algebraic effects）：当脚本执行遇到未处理的效果（如 perform Log(「Hello, World!」)）时，解释器返回 unhandled_effect 及完整程序状态；Erlang 宿主通过 loop 函数匹配该中断，调用 extrinsic 实现具体效果（如将字符串输出到控制台），再以 resume 恢复执行。最后加入类型检查阶段：在运行前调用 eyg_analysis 的类型推断，通过 effect context 声明可用效果（如 Log），推断结果可确保通过类型检查的程序无运行时错误。文章指出，扩展脚本能力只需向推断上下文添加新的 effect handler 及其对应类型，即可将更多应用逻辑安全地暴露给脚本用户。
