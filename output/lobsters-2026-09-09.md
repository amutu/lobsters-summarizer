## 1. 我将软件许可证切换为欧盟公共许可证（EUPL）

- 原始链接: <https://bergie.iki.fi/blog/eupl/>
- 英文标题: I changed my license to EUPL

作者回顾了自己28年软件发布生涯中的三次许可证转变：早期Midgard框架采用LGPLv2弱copyleft许可证；2011年前后转向MIT许可证以融入NPM生态；今年则全面切换为欧盟公共许可证EUPL-1.2。作者认为，过去开源阵营推崇的宽松许可证（permissive license）虽在理念之争中「赢了」，但实际效果只是让大公司更廉价地构建产品、让富豪积累更多财富，对普通用户和开发者并无实质好处。EUPL作为OSI认可的强copyleft许可证，通过要求无论以何种方式分发软件都必须互惠授权，有效关闭了「SaaS漏洞」；此外，EUPL拥有23种语言的官方合法译文，更契合全球范围内软件的实际使用场景。作者已将reticulum-js（网状网络协议）、dacar（去中心化授权系统）、signalk-energy-predictor（可再生能源船舶预测）、offshore-blogging-system（卫星通信博客工具）及NoFlo开发环境重写版等项目置于EUPL之下，而NoFlo本体因存在大量第三方贡献仍保留MIT许可证。作者明确表示，若企业不愿遵守其条款，可自行投入资源构建替代方案。

## 4. 极端服务端渲染（XSSR）：无需前端 JavaScript 的动态网页

- 原始链接: <https://www.scd31.com/posts/extreme-server-side-rendering>
- 英文标题: Extreme Server Side Rendering

本文提出「极端服务端渲染」（XSSR）概念，即在保持 HTTP 连接不关闭的前提下，由服务端持续向浏览器推送 HTML 与 CSS，实现完全无需前端 JavaScript 的动态页面更新。文章先回顾传统 SSR 的两种形态：纯服务端生成 HTML 的旧式 SSR，以及结合前端 JS 处理交互的新式 SSR。XSSR 的核心在于利用浏览器逐行渲染 HTML 的特性，通过长连接实现 60FPS 实时画面更新。用户输入方面，作者采用隐藏 iframe 配合表单提交的技巧避免页面刷新。实践部分以 Flappy Bird 克隆为例，物理引擎运行于后端 Rust 服务，每核可支撑约 500 个并发游戏，带宽仅约 20KiB/s，但延迟受网络距离影响显著。文章还提到该技术在 Fediverse 平台引发 Pleroma 服务器间歇性宕机，最终作为 DoS 漏洞被修复。未来方向包括构建纯服务端 React 框架，以及为不支持 JS 的旧设备提供代理渲染服务。

## 6. Bitap：我最喜爱的字符串匹配算法

- 原始链接: <https://jo3-l.dev/posts/bitap/>
- 英文标题: Bitap: my favorite string matching algorithm

本文从最朴素的暴力字符串匹配算法出发，逐步推导出bitap（又称shift-and）算法。作者先将朴素算法改造为流式版本，维护一组「进行中匹配」状态，每读入一个字符即推进或淘汰这些状态；随后将状态集合用整数索引表示，再压缩为位集（bitset）；最终通过两个关键位操作——左移一位（active << 1）推进所有状态、与预计算掩码（validMask[c]）做与运算剔除非法转移——消除内层循环，得到简洁高效的bitap算法。作者还提及shift-or变体（用OR代替AND，每字符少一次位操作）。文章指出bitap在模式串较短（长度小于机器字宽，如64位）时表现优异，概念优雅、易于从朴素算法推导，远不如Boyer-Moore或KMP那样难以理解。但作者也坦诚其局限：对长模式串优势递减，渐近复杂度与朴素算法同为线性，预计算开销可能使单次测试反而更慢。此外，「bitap」一词也可指支持Levenshtein距离的模糊匹配变体，但本文仅讨论精确匹配。

## 7. 给电子墨水阅读器装一台「打印机」

- 原始链接: <https://nishantjosh.dev/blogs/how-to-build-a-fking-printer/>
- 英文标题: How to build a f**king printer

作者入手了可编程电子墨水阅读器 Xteink X3，发现向设备传文件需手动连热点、开网页上传，十分繁琐。他由此产生一个念头：既然设备看起来像纸，就该能像纸一样被打印。于是他在设备端实现了 IPP（Internet Printing Protocol），让 MacBook 在打印对话框中直接选择名为「penguin」的打印机。具体做法包括：通过 Bonjour 广播 _ipp._tcp 服务（并加入 _universal 子类型以触发 macOS 无驱动发现），声明单色、300 dpi、A5/Letter 纸张等能力，接受 Apple Raster 与 PWG Raster 格式。核心难点在内存：300 dpi 的 Letter 页约 8.4 MB，而 X3 仅有 400 KB RAM，扣除 Wi-Fi 与屏幕缓存后仅剩约 6.8 KB 堆空间。作者放弃在 RAM 中构建完整图像，改为逐行解码、缩放、抖动后直接写入显示屏帧缓冲区，处理完一行即复用工作区，最终将整页保存为 BMP 到 SD 卡。改造后图像缓冲占用从约 113 KB 降至约 62 KB，为网络栈腾出空间。最终效果：在 Mac 预览中打开一张漫画页，选择「penguin」打印，约一秒后画面即出现在屏幕上。打印机服务可加入 Wi-Fi 或自建热点「literate-penguin」，打印件以文件夹形式留在 SD 卡中，相当于一个「出纸托盘」。代码已开源至 CrossPoint 固件分支。

## 11. Rust 中的空类型并非底类型

- 原始链接: <https://ettolrach.com/blog/rust_when_empty_isnt_bottom.html>
- 英文标题: Rust: When Empty Isn't Bottom

本文围绕 Rust 1.100 即将支持的「never」类型（记作 !）展开，核心论点是：空类型（empty type）与底类型（bottom type）在类型论中并非同一概念，Rust 的 ! 属于前者而非后者。空类型没有值和构造器，通过 absurd 函数或模式匹配进行消除，不依赖子类型系统；底类型同样无值无构造器，但通过子类型预序中「最小元素」的定义（对所有类型 A 有 ! <: A）来使用，必须有子类型机制。Rust 缺乏通用子类型，因此只能实现空类型。文章用 Scala 的 Nothing 与 Rust 的 ! 对比，指出关键实践差异：当 ! 嵌套在函数类型等复合类型中时，Rust 不会自动进行类型强制转换（coercion），需手动解构再转换，而 Scala 借助协变性可自动处理。作者还追溯了混淆的根源——Wikipedia 相关词条的表述容易让读者误以为两者等价，并补充了 Haskell 惰性求值下 Void 的特殊行为作为对照。结论是：Rust 虽无底类型，但表达能力并不逊色，只是写法稍显繁琐。

## 13. 我分解了上世纪90年代某证书机构的RSA密钥

- 原始链接: <https://mcpherrin.ca/2026/09/07/rsa.html>
- 英文标题: I’ve factored the RSA keys of a Certificate Authority…from the 90s

作者Matthew McPherrin出于对RSA安全性的好奇，尝试分解早期Web PKI中遗留的小位长RSA根证书。他从archive.org下载了Netscape和IE的旧版安装包，借助Claude Code提取出大量历史根证书，发现1999年Netscape 4.51曾内置加拿大已倒闭CA「E-Certify」的两枚512位RSA根证书（分别用于SSL和S/MIME）。作者使用CADO-NFS在Ryzen 9 5950X台式机上完成分解：SSL密钥耗时32小时，S/MIME密钥耗时29小时，成功恢复出对应私钥。随后他在虚拟机中运行Netscape 4.51并用Go编写了一个兼容旧版TLS的测试服务器（e-certify.fly.dev），验证了用恢复的私钥签发证书仍可被该浏览器信任。此外，IE 3.02中一枚VeriSign测试CA的512位密钥也被分解。文章指出，这些密钥早在2002年即被Netscape移除，且需时钟回拨至2003年前才能利用，实际威胁为零，但实验揭示了早期PKI缺乏最低密钥长度标准的隐患。所有密钥与工具已开源至GitHub。

## 14. Emacs Bedrock 2.0 发布

- 原始链接: <https://lambdaland.org/posts/2026-09-06-bedrock-v2/>
- 英文标题: Emacs Bedrock 2.0 Released

Bedrock 是一个极简、手工打造的 Emacs 启动配置套件，2.0 版本现已发布，要求 Emacs 31（2026年8月发布）。其核心理念是提供「更好的默认值」，基础配置不依赖任何第三方包，仅由 early-init.el 和 init.el 两个文件组成，用户复制到 ~/.emacs.d/ 后直接修改；第三方包配置放在 extras/ 目录，按需引入。2.0 主要变更包括：所有 .el 文件启用 lexical-binding: t；use-package 声明的包默认自动安装；用 embark-auto-prefix-help-mode 替代 which-key；移除 wgrep 改用内置 grep-change-to-grep-edit-mode；大幅改进 tree-sitter 与 isearch 配置；Completions 缓冲自动更新；默认开启 repeat-mode。作者强调这是增量改进而非全面重构，老用户未必需要升级。Bedrock 不支持自动升级路径，用户需手动对比新旧 commit 选取所需变更。作者 Ashton 表示 Bedrock 最初只是个人练习，后发展为社区广泛使用的配置起点，并感谢社区贡献与反馈。

## 18. 从易变拨号IP提供Web服务：用Cron与SSH轮询更新反向代理

- 原始链接: <https://blog.mro.name/2026/09/web-from-dial-up/>
- 英文标题: Serving Web from volatile Dial-up IP

作者的家庭实验室通过不稳定的拨号IP接入互联网，IP会因意外重连而频繁变化。虽然已配置动态DNS，但作者更倾向于在客户端与服务器之间部署反向代理，而动态DNS无法主动通知反向代理IP已变更。文章提出的核心思路是「没有推送就轮询」：在家庭实验室服务器上设置一条每15分钟执行一次的cron任务，调用本地脚本 http-up.sh。脚本先用 curl 检测本地服务是否可达；若检测失败（说明IP已变），则通过 SSH 连接远程 VPS，利用 SSH_CLIENT 环境变量提取当前新IP，再用 envsubst 将IP填入反向代理配置模板（.tpl），生成最终配置文件，最后执行 sudo service lighttpd reload 使新配置生效。整个方案仅依赖 cron、curl、SSH 和 envsubst，无需引入额外服务或工具。作者认为15分钟的延迟完全可以接受，且由易变主机主动通知被动反向代理，架构简单、无第三方依赖，适合个人 homelab 场景。
