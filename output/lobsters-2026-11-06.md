## 1. sshhole：1980年 /etc/passwd 中一个星号的故事

- 原始链接: <https://sshhole.com/>
- 英文标题: sshhole

本文回顾了早期 Unix 系统中 /etc/passwd 文件的一段历史。在 1980 年前后的旧版 Unix 中，用户密码的哈希值直接存放在 /etc/passwd 文件里，与用户名并列，且该文件对所有用户可读，存在明显的安全隐患。1980 年，Bill Joy 为系统账户 daemon 在密码字段中放置了一个星号「*」。由于「*」并非合法的哈希值，任何输入都无法与之匹配，因此无人能以该账户登录——daemon 本就不应被任何人使用。这一做法沿用至今，成为 Unix 系统中禁用账户登录的经典手段。文章还提到一个细节：Bill Joy 将 daemon 账户的 real name（真实姓名）字段写成了「the devil himself」（魔鬼本人），为这段技术史增添了一丝幽默。全文引用了 3BSD 版本的 /etc/passwd 源码作为佐证，篇幅短小但信息明确，属于 Unix 历史趣闻类内容。

## 3. 声明式拖拽：用未来状态定义交互

- 原始链接: <https://declarative-dragging.github.io/>
- 英文标题: Declarative Dragging

本文介绍发表于UIST 2026并获最佳论文奖的「声明式拖拽」(Declarative Dragging, D2)系统。传统拖拽交互需开发者手动处理几何计算、视觉反馈与动画，门槛高、代码繁琐，导致许多教育者、游戏设计师和创意工具构建者放弃使用。D2反转了这一思路：开发者只需为每个可拖拽元素声明拖拽后应用应到达的未来模型状态，引擎便推测性渲染这些状态、提取元素在各渲染中的位置，自动合成平滑的拖拽体验。系统具备模型驱动与可组合两大特性，支持浮动、吸附、过渡等修饰器叠加。作者将D2实现为面向Web SVG的Dragology库，展示了代数、扭曲树、贝塞尔曲线、辫子、卡牌堆、三格骨牌等丰富示例。项目起源于Andrew 2022年做数学游戏时的白板草图，2023年与Josh交流后逐步成型。论文发表后，Dragology已应用于Hazel学术编程环境（使代码重构变得可感知、可发现）及面向手柄与3D场景的数学游戏。该系统尤其适合并行表示界面，能在拖拽过程中实时联动更新多种视图，直观呈现同一系统的不同视角。

## 4. Datastar 框架初探：服务端驱动的响应式 Web 应用

- 原始链接: <https://noteflakes.com/articles/2026-11-04-datastar>
- 英文标题: A Look at Datastar

作者是一名后端程序员，长期关注前端响应式方案。文章介绍了 Datastar——一个自称「超媒体框架」的声明式交互库（仅约 15KB），它通过 HTML 属性实现响应与交互，类似 HTMX 或 Alpine.js，但核心理念是状态始终留在服务端，由服务器通过 SSE（服务器推送事件）持续向客户端发送 HTML 补丁或信号补丁，而非将服务端状态复制到浏览器。与 LiveView 类似但语言无关，Datastar 提供了 Ruby、Elixir 等多语言 SDK。作者通过一个实时时钟示例展示了其用法：客户端仅需 data-init 和 data-text 属性，服务端每秒推送一次信号更新。文章还讨论了信号的全局性、命名空间机制、无 JavaScript API 的设计取舍，以及 Datastar 偏向多页应用（MPA）而非单页应用（SPA）的哲学。作者提到 Instabooks（Quickbooks 的快速 Web 界面）中每次用户交互都触发整页重渲染，证明该方式在轻量运行时下既快速又简洁，能大幅减少前端 JS 并简化测试。最终作者从最初的抵触转为认同，计划将 Datastar 集成到自己的 Ruby 框架 Syntropy 中，认为这种「UI = λ(state)」的服务端渲染思路为构建 Web 应用开辟了全新路径。

## 5. SourceHut 注册关闭绕过漏洞（CVE-2026-121728）

- 原始链接: <https://blog.arusekk.pl/posts/srht-disabled-registration-bypass/>
- 英文标题: SourceHut disabled registration bypass | CVE-2026-121728

安全研究员披露了 SourceHut 代码托管平台的一个注册绕过漏洞（CVE-2026-121728）。SourceHut 在架构重构中，将前端从 Flask/Jinja/SQLAlchemy 迁移至 Go 语言 GraphQL API。2021 年迁移注册逻辑时引入了一处细微缺陷：前端始终显示「注册已关闭」，但后端表单处理函数在所有错误路径上正确返回「注册已关闭」，唯独在成功路径上未做该检查。攻击者只需向 /register/step2 发送 POST 请求，携带用户名、邮箱、密码及 CSRF token 即可完成注册。CSRF token 虽无法从已隐藏的注册表单获取，但 /login 页面的 token 可通用，从而绕过防护。漏洞影响 0.56.11 至 0.88.9 版本，至少 10 个实例受影响，CVSS 4.0 评分为低危。作者于 2026 年 11 月 2 日向 SourceHut 安全邮件列表披露，次日修复合入并通知下游。文章总结了三条教训：重构可能意外吞掉安全检查；认证流程需反复验证正确性；CSRF token 应限定到具体端点而非全局通用。

## 7. 每词11纳秒：对变位词查找的极致过度优化

- 原始链接: <https://wiredream.com/anagram-fun/>
- 英文标题: 11 nanoseconds per word: Ridiculously Over-Optimizing Anagrams

本文作者David G. Andersen以Scrabble词典（178,690个词条）为对象，展示了将变位词（anagram）索引构建时间从31毫秒（每词173纳秒）逐步压缩到1.96毫秒（每词10.9纳秒）的完整优化历程，共实现约15.8倍加速。优化路径包括：（1）用扁平数组加内联单例消除大量Vec动态分配；（2）将字母计数以每字母4位打包进u128，避免字符串排序；（3）换用rustc_hash::FxHashMap替代默认哈希表；（4）核心亮点——采用Gödel编号思想，为26个字母各分配一个素数，以素数乘积作为字母集合的无碰撞64位标识符，且素数分配并非按通用字母频率，而是针对词典中3157个15字符长词的实际模式调优（如E→2、I→3、T→29、J→101），最大乘积词PSYCHOPATHOLOGY约为64位空间的96.2%；（5）将输入词以每字符5位打包为u128，配合双累加器利用指令级并行；（6）将循环改为定长16字符无分支形式，使编译器自动向量化。文章强调这是「过度优化」的趣味实践，并预告下篇将用此变位词索引解决完整的单词梯（Word Ladder）问题。

## 8. lobste.rs 已登录用户为何仍被 Anubis 搜索门拦截

- 原始链接: <https://lobste.rs/s/y4poxs/why_is_there_anubis_gate_front_search_for>
- 英文标题: Why is there an Anubis gate in front of Search for logged-in users?

lobste.rs 是一个邀请制社交技术社区，有用户发现即使已登录，访问搜索功能时仍会先经过 Anubis（一种基于 Caddy 的反爬/速率限制中间件）验证门。用户质疑：既然站点是邀请制，攻击者必然已登录，完全可以基于身份做速率限制，无需对已登录用户再设 Anubis 门。开发者 355E3B 回应称，编写配置时似乎没有方法检测已登录用户的 cookie；且站点通过 Hatchbox 部署，Caddy 配置受限，被锁定在「Caddy → Anubis → Rails」的固定流程中，难以灵活跳过。社区成员 mjec 提出可行方案：在 Caddyfile.pre 中根据 has_user_cookie 设置合成请求头，再在 Anubis 配置中据此放行；也可检查 lobster_trap cookie，但需配合将无效 cookie 用户重定向至登录页以确保安全。该问题已在 GitHub issue #1781 中讨论。另有用户反映近几个月频繁被登出，开发者认为可能是浏览器 cookie 存储配置问题，与 Anubis 无关。整体而言，这是一个部署架构限制导致的配置问题，社区已给出改进思路并计划提交 PR。

## 9. 23000个量子比特能否破解RSA-2048？

- 原始链接: <https://www.bfswa.blog/p/can-23000-quantum-qubits-break-rsa>
- 英文标题: Can 23,000 quantum qubits break RSA-2048?

法国量子计算公司Alice & Bob在密码学预印本平台ePrint上发表论文，声称其未来可能建造的量子计算机仅用22593个量子比特、约π天（3.14天）即可通过Shor算法分解RSA-2048。文章作者（量子计算研究者Scott Aaronson）对此进行冷静评析，指出该研究虽属扎实的量子工程估算，但存在巨大假设鸿沟：论文假设比特翻转错误平均每量子比特每100年发生一次，而A&B已公开实验的结果是每几分钟一次，两者相差逾一亿倍；此外A&B目前仅实现18个猫量子比特，距所需规模尚差22575个。论文另提出一种更保守的45000量子比特方案，但依赖尚未演示的错误纠正技术。作者强调，计算一台假设机器能做什么，与证明我们已具备建造它的能力，是两件截然不同的事。他同时指出，量子公司间的竞争正演变为「注意力竞争」，各方倾向于发布看似惊人的数字以吸引关注，但A&B的论文在假设透明度上做得不错。此外，该论文还声称用约30000量子比特可在约一小时内解决256位ECDLP问题。总体而言，资源估算本身有价值，但读者应警惕「OMG量子」式标题带来的恐慌。

## 11. ELF（可执行与链接格式）

- 原始链接: <https://en.wikipedia.org/wiki/Executable_and_Linkable_Format#86open>
- 英文标题: 86open

ELF（Executable and Linkable Format，可执行与链接格式）是Unix及类Unix系统中广泛使用的标准二进制文件格式，涵盖可执行文件、目标代码、共享库、设备驱动和核心转储。该格式由Unix System Laboratories开发，1998年5月首次发布，1999年被86open项目选定为x86平台上Unix系统的标准二进制格式。ELF设计灵活、可扩展且跨平台，支持不同字节序与地址宽度，因此被众多操作系统和硬件平台采用。文件结构上，每个ELF文件由ELF头、程序头表和节头表组成：ELF头（32位52字节/64位64字节）包含魔数0x7F「E」「L」「F」、目标架构、ABI版本等字段；程序头表描述运行时内存段；节头表记录链接与重定位所需的节信息。ELF已取代a.out和COFF等旧格式，广泛应用于Linux、Solaris、FreeBSD等系统，也延伸至游戏主机（PlayStation、Wii等）、移动设备（Android、Symbian）及区块链平台（Solana以ELF格式部署智能合约）。常用分析工具包括GNU Binutils中的readelf与objdump，以及elfutils等替代方案。

## 12. Flink Kafka 连接器如何向 Kafka 提交消费位移

- 原始链接: <https://dalelane.co.uk/blog/?p=6161>
- 英文标题: How Flink's Kafka connector commits offsets to Kafka

本文记录了作者修复 Flink Kafka 连接器在事务性 topic 上提交消费位移（offset）问题的完整过程（对应 FLINK-33484）。问题根因：Flink 每处理一条记录便将 split 位移加 1，但 Kafka 消费者实际已越过事务标记（commit/abort marker），导致 Flink 提交的位移始终落后于消费者真实位置，监控显示虚假 lag。初始修复思路为：在 checkpoint 完成时，若 checkpoint 位移恰好等于「最后取出的记录位移 + 1」，则改用消费者当前位置提交，从而跳过不可见的标记条目。经多轮 review，作者陆续修补了若干边界情况：Flink 自身 committedOffset 指标与 Kafka 实际提交值不一致、从未交付记录的分区（如仅含 aborted 事务）、占位符位移 EARLIEST_OFFSET（-2）尚未被真实位移替换、以及新记录在 checkpoint 与 commit 之间到达导致位移回退等问题。最终方案在 fetch 阶段记录 lastKnownPositions 与 lastFetchedOffsets，commit 时进行 reconcile，并保证已提交位移不回退。作者强调此改动不影响 Flink 的 exactly-once 处理保证，仅修正 best-effort 的 Kafka 侧位移上报。文章还指出 stop-with-savepoint 场景下位移仍未提交至 Kafka（FLINK-36532）等遗留问题。
