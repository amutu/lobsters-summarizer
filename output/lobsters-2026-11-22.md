## 1. 用 Jujutsu 空提交管理 TODO 的工作流

- 原始链接: <https://bwc9876.dev/blog/jj_todo/>
- 英文标题: TODOs JJ Style

作者分享了一种基于 Jujutsu（JJ）版本控制工具的 TODO 管理方法。传统做法是将待办事项写入仓库内的 TODO.md 文件，但作者发现这种方式容易遗忘、难以及时勾选完成项，且因为文件在仓库中，往往不想随手更新。作者转而利用 JJ 的空提交（empty commit）功能：把每条待办事项创建为一个带有描述的空提交，构成一棵「TODO 树」。当准备着手某项任务时，只需将该空提交 rebase 到实际工作分支上即可开始开发；而 TODO 基线本身因为全是空提交，前移时永远不会产生冲突，移动非常轻松。对于存在依赖关系的待办事项，只需在已有空提交之上再叠加新的空提交，依赖关系便自然表达。为防止这些个人待办被推送到远程仓库，作者通过 git.private-commits 配置，将描述以「private:」为前缀的提交标记为私有，确保它们仅保留在本地。配置示例通过 Home Manager 中的 jujutsu 设置实现。作者坦言这一方法并不 groundbreaking，但确实契合个人工作习惯，是一种轻量且实用的 TODO 管理思路。

## 2. Go 中的概率数据结构（二）：Binary Fuse Filter、UltraLogLog 与对数线性直方图

- 原始链接: <https://antonz.org/probabilistic-data-structures-2/>
- 英文标题: Probabilistic data structures in Go, part 2

本文是 Go 概率数据结构系列第二部分，基于 unsure 包介绍三种新结构并给出基准测试。Binary Fuse Filter 是一种静态集合过滤器，构建后不可增删，相同误报率下比 Bloom filter 节省约 36% 内存，适合不可变文件键集合、已知坏项列表等写一次读多次的场景；其原理是将元素哈希后取 b 位指纹与三个数组位置，通过 XOR 校验完成查询，使用 wyhash 哈希，查询速度与 Bloom filter 相当但构建慢约 2.5 倍。UltraLogLog 是 2024 年 Otmar Ertl 提出的唯一项计数器，在每个寄存器中额外记录 k-1、k-2 是否出现过，相同精度下比 HyperLogLog 节省约 43% 内存，但添加、计数和合并操作明显更慢。对数线性直方图用于估计分位数，将值域按 2 的幂划分为 octave 再等宽分桶，避免了对数计算；添加速度与 HdrHistogram 相当，查询快 5 至 19 倍，合并快 35 至 175 倍；与 t-digest 相比，它限制的是值误差而非排名误差，在长尾分布下精度优势显著，更适合延迟、文件大小等正数测量场景。

## 3. 把 Postgres 塞进一个二进制文件：miniPG 的诞生

- 原始链接: <https://progrium.xyz/articles/2026/single-binary-postgres>
- 英文标题: How I Got Postgres into a Single Binary

作者介绍 miniPG 项目，目标是让 Postgres 拥有类似 SQLite 的使用体验：指向一个目录即可执行查询，无需启动服务器或安装 Docker。miniPG 是一个跨平台（Mac/Windows/Linux）的单一可执行文件，内部嵌入完整的 Postgres 服务端与客户端，数据以文件形式存于指定目录，闲置时只是磁盘上的文件，可随时复制、备份或删除。作者经历了三次技术尝试：第一次基于 PGlite（WASM 版 Postgres），但因仅支持单连接单会话，导致多连接场景下死锁；第二次在 webview 中运行 v86 x86 模拟器承载 Postgres，方案可行但启动需 7 秒，体验不可接受；第三次借助自研的 Hyper9（基于 Plan 9 系统 API 翻译与虚拟化技术），将启动时间降至 800 毫秒，最终完成 miniPG。该项目适用于本地单用户场景，如自托管工具、需要 JSONB 或全文检索等 Postgres 特性的应用、测试与 AI agent 等，但并非生产环境 Postgres 的替代品。作者认为这一模式可推广到将复杂系统打包为单一二进制的更广泛场景。

## 4. freedesktop.org 网站与 Wiki 改版上线

- 原始链接: <https://blog.tenstral.net/2026/11/new-fdo-website.html>
- 英文标题: Changes on freedesktop.org

freedesktop.org 正式启用了全新主网站与翻新后的 wiki.freedesktop.org。改版背景是：该站点自 2000 年起以 Wiki 形式运营，虽契合跨桌面协作的初衷，但多年积累导致官方信息、已完成规范、半成品提案与长期无人维护的页面混杂在一起，新参与者难以判断哪些内容仍然有效；同时多次遭遇垃圾信息攻击，2013 年已切换至 IkiWiki 并严格限制写入权限。此次改版将「官方/精选信息」与「协作编辑」分离：主网站定位为更 curated 的信息门户，采用 Pelican 静态站点经 GitLab Pages 托管；Wiki 则继续承担协作功能，但编辑方式从旧 IkiWiki 网页界面改为通过 GitLab 提交，并为此重写了 Git 历史以保持内容目录结构一致。作者表示接下来将开展内容盘点，区分活跃与归档项目、补齐缺失条目、同步 specifications.fd.o 上的规范列表，并推进网站与 Wiki 之间的去重工作。文章同时感谢了历年贡献者及 Sovereign Tech Agency 的 fellowship 项目支持，并邀请社区通过 issue 或 merge request 反馈问题。

## 5. 从跳表到 B+ 树：让 Valkey 有序集合更省内存

- 原始链接: <https://valkey.io/blog/from-skiplist-to-b+tree/>
- 英文标题: From Skiplists to B+ Trees: Making Valkey Sorted Sets More Memory Efficient

Valkey 9.2 将大型有序集合的底层索引从跳表替换为一种名为 fbtree 的高扇出 B+ 树变体。跳表每节点仅存一个元素，指针与跨度开销约 37 字节/节点，且节点分散在堆上，导致大量缓存未命中和依赖式内存访问。fbtree 采用 61 路扇出、连续存储，将 score 与 member 打包为单一值，并引入多项优化：内节点用四字节「特征」配合 SIMD 并行比较以快速定位子节点；叶子节点以双向链表相连，使 ZRANGE 等范围扫描无需回爬树；左右端叶子被缓存，ZPOPMIN 等操作保持 O(1)。在 500 万成员的测试中，每成员内存开销从 50.3 字节降至 28.5–32.0 字节，减少 36%–43%，顺序插入场景下节省约 109 MB。吞吐方面，ZADD 提升 105%、ZREM 提升 76%、ZCOUNT 提升 27%，而依赖哈希表的 ZSCORE、ZRANDMEMBER 几乎不变。对用户而言，命令行为完全不变，唯一可见差异是 OBJECT ENCODING 对大型有序集合返回「btree」而非「skiplist」，相关监控脚本需相应更新。Valkey 9.2 目前处于发布候选阶段，作者建议用户在真实负载上提前测试并反馈问题。

## 6. Enroute 水平扩展 Git：超越 Multi-Raft 的共识架构演进

- 原始链接: <https://enroute.sh/blog/scaling-horizontally-how-we-moved-beyond-multi-raft>
- 英文标题: Scaling Git horizontally: how we moved beyond Multi-Raft

Enroute 是一个将计算与存储分离的 Git 托管平台，集群由计算节点、Ledger 节点和对象存储桶组成。早期采用 Multi-Raft 方案，每个仓库拥有独立的 Raft 组，但在 10 万仓库、2048 并发写入时，心跳延迟引发数千次选举，吞吐量骤降至 1500 次/秒。团队虽通过让空闲日志休眠、将存活检测上移到节点层等修补手段将吞吐提升至 1.4 万次/秒，但复杂度持续累积。为此，Enroute 引入「根日志」作为外部 sequencer，借鉴 Vertical Paxos 思想：由根日志统一决定各仓库分片日志的 sequencer 归属，分片日志副本不再自行超时或竞选，仅在旧配置被多数封禁后才切换新 sequencer。日志写入仍沿用 Raft 的复制与提交规则。根日志 leader 同时承担放置职责，可将副本分散到不同可用区并均衡负载。验证方面，团队用 Stateright 对核心状态机做穷举模型检查，并用 Jepsen 在真实进程中注入故障。性能测试显示，0.4.0 版本在 30 万仓库下可达 2.4 万次/秒推送，p99 延迟仅 47 毫秒，Ledger 节点仅占用 4 核中的约 2.5 核。未来计划包括持续放置优化、根日志 learner 模式、时间点恢复以及计算层内部路由。

## 7. DNS Stamps 规范

- 原始链接: <https://dnscrypt.info/stamps-specifications/>
- 英文标题: DNS Stamps Specification

DNS Stamps 是一种将连接安全 DNS 服务器所需的全部参数编码为单一字符串的规范，类比于 DNS 领域的 QR 码。所有 stamp 以「sdns://」为前缀，后接 base64url 编码的拼接数据。规范定义了基础编码原语（LP、VLP、vlen 等），并针对多种协议规定了各自的 stamp 格式：Plain DNS（0x00）、DNSCrypt（0x01）、DoH（0x02）、DoT（0x03）、DoQ（0x04）、Oblivious DoH 目标（0x05）、匿名化 DNSCrypt 中继（0x81）及 Oblivious DoH 中继（0x85）。各格式包含协议标识符、属性位（如 DNSSEC 支持、无日志、不封锁域名）、服务器地址、证书 SHA256 哈希（支持多哈希以实现无缝轮换）、主机名、路径及可选的引导 IP 等字段。文章还列出了 Go、Rust、Python、JavaScript、Swift、.NET 等多语言实现库，以及 dnscrypt-proxy、AdGuard、NextDNS 等已采用该规范的应用，并提供了 Quad9、CleanBrowsing、OpenNIC 等公共解析器列表。该规范的核心目标是简化安全 DNS 配置的分发与交换，使用户可通过一个短字符串完成服务器连接的全部配置。
