## 1. 我喜欢的一些软件演讲

- 原始链接: <https://char.lt/blog/2026/08/talks-i-like/>
- 英文标题: some software talks i like

作者从大量软件演讲中筛选出自己欣赏的几场，主题聚焦于软件开发技艺本身，而非具体工具或部署。文章首先引用Rich Hickey在Strange Loop 2011的《Simple made easy》，强调“complect”一词，说明复杂性源于概念的纠缠，而简单（sim-plex）意味着单一折叠。接着是Bryan Cantrill在TalosCon 2025的《The Complexity of Simplicity》，提出从“简单/复杂”与“工程化/涌现”两个轴对系统分类，得出构造、反叛、堆积、革命四种类型，用于思考依赖与系统。Allison Parrish的《Programming is Forgetting》将编程视为量化与刻意遗忘，认为代码必然带有特定视角并排除其他可能性。Steve Klabnik的《Steel, Rust, and truth》讨论AI时代软件工程师的焦虑与机器编写软件的正确性问题。Andrew Kelley的《Don't take the black pill!》则传递希望，认为技术取决于人性，并呼吁击败利用计算机胁迫他人者。Mike Acton的《Solving the right problems》强调在具体上下文与约束下解决问题，而非抽象化。Will Wilson的《Swarm Testing》涉及软件测试，但作者保留悬念。最后Tyler Neely的《Throwing it all away》介绍“一天内扔不掉就重写”的极端方法，以控制复杂度和保持系统可理解。作者对这些演讲给予高度评价，并指出演讲领域目前以男性为主的现象。

## 5. Jolt 新特性：程序镜像与可移植 Scheme 后端

- 原始链接: <https://yogthos.net/posts/2026-08-07-portable-jolt.html>
- 英文标题: Program images and portable Scheme backends for Jolt

本文介绍了 Jolt 近期实现的两个新特性，二者都源于松解 Jolt 与宿主运行时之间的耦合。第一个特性是程序镜像（program image），借鉴 Common Lisp 和 Smalltalk 的风格，允许将程序运行时的完整状态序列化到磁盘。具体而言，jolt.image 库提供 image/dump! 和 image/dump-world! 两个函数，可在异常处理中捕获整个程序状态（包括变量、数据结构、闭包等），并生成架构无关的镜像文件。后续可在 REPL 中恢复镜像，直接检查出错时的内存值，甚至调用出错时失败过的函数来复现问题，从而避免了传统日志难以预判问题、过度记录等问题。对于无法序列化的开放资源（如 socket、文件端口），默认以桩记录方式处理，并可注册解析器恢复。第二个特性是实现了可移植的 Scheme 后端，将编译器拆分为核心层、适配器契约层和目标相关文件层。适配器契约定义了 72 个 sa-* 入口点，按功能分级，允许部分实现或明确降级。Chez Scheme 仍是默认目标，而 Gambit 作为第二后端，其 JavaScript 后端使 Jolt 能在浏览器中运行，官方站点已提供交互式 REPL 演示。该重构使 Jolt 可借助更多 Scheme 实现，让同一份 Clojure 程序跑在服务器、浏览器或小型静态二进制中，体现了程序不应被初始进程或原始运行时束缚的理念。

## 6. 汇编耻辱堂：竞逐CPU性能底谷

- 原始链接: <https://github.com/xoreaxeaxeax/asm-hall-of-shame>
- 英文标题: Assembly Hall of Shame: Racing to the bottom of CPU performance

本文介绍一个名为“Assembly Hall of Shame”的反向性能优化研究项目。传统指令延迟分析追求让代码尽可能快，而该项目反其道而行之，专门寻找单条指令性能的绝对下限。文章给出了x86平台上的排行榜，从最慢的nop（1周期）到当前冠军fxrstor64（约1980亿周期、耗时62秒）。冠军策略是：用fxrstor64从PCIe架构中的高延迟MMIO区域加载512字节的FPU/MMX/XMM状态，同时让多个“锤击”核心对另一个高延迟MMIO寄存器进行紧促的4字节读取，以此饱和PCIe根复杂设备和端点的事务队列，使目标指令被迫排在大量非投递事务之后。其他上榜指令包括rdtsc、idiv、enter、fldl、clflush、fsin、mfence、mov cr3、fadd、split lock、fdiv、cpuid、rdrand、wrmsr、out、rdmsr、wbinvd、in等，每项都附有具体策略、测试机型、周期数和时间。文章还提到利用未对齐的ymm0加载迫使GPU寄存器产生非投递dword事务，从而破坏系统管理模式设计，以及一个尚未实施的xrstor64（AMX、MMIO）构想。目前仅公布x86排行榜，ARM和RISC-V榜单待定。项目由Christopher Domas发起，旨在探索极端硬件行为边界。

## 8. 修订提示：提升工业LLM流程的效率与一致性

- 原始链接: <https://revisionprompting.info/>
- 英文标题: Revision Prompting improves industrial LLM processes

文章介绍了一种名为“修订提示”（Revision Prompting）的LLM提示技术，用于改进工业场景中重复执行相同指令的自动化流程。传统方法在输入数据更新后，会重新对整个输入运行指令，导致两个问题：一是LLM的非确定性使得输出在必要变更之外产生额外差异，缺乏一致性；二是全量重新处理耗费时间与token成本。修订提示通过让LLM基于原始输入、原始输出以及输入差异（diff）生成针对输出的补丁（patch），再将补丁应用到原始输出上，从而得到更新后的输出。文中以电动自行车产品页翻译为例：当续航从80公里改为100公里时，模型只需输出改动相关的两行翻译补丁，而不是重新翻译整页。该方法有效的原因在于：补丁严格对应输入变更，未触及部分保持原样，保证了输出一致性；同时模型只生成短补丁，大部分token从输出端转移到输入端，处理时间大幅缩短，输出成本转为更低的输入成本，且若在短时间内重跑，提示缓存还能进一步降低输入成本。实际使用中，差异和补丁的格式可选用POSIX diff或JSON Patch等。根据作者的经验，该技术使时间减少约80%，成本降低约65%。

## 9. OpenSSH 密钥结构指南

- 原始链接: <https://sshref.dev/>
- 英文标题: OpenSSH Key Structure Guide

本文是一份详尽的 OpenSSH 密钥格式技术指南，旨在补充官方文档的不足。文章首先区分了旧版（Legacy，OpenSSH 7.8 之前）与新版 "v1" 格式：旧版私钥直接采用标准 PEM 编码，公钥则统一为“类型 + Base64 编码密钥 + 注释”的文本行；新版私钥则包含更灵活的特性，如可自定义加密算法与 KDF、内嵌注释和公钥、以及用于校验解密是否正确的校验和。随后，文章针对 RSA 和 ED25519 两种常见密钥类型，逐一拆解公钥与私钥的二进制结构。对于 RSA，详细给出了公钥中指数 e 与模数 n 的排列方式，以及私钥在 Legacy 明文、Legacy 加密、v1 明文、v1 加密四种情况下的字段布局，包括 PEM 头（如 Proc-Type、DEK-Info）、v1 格式中的 openssh-key-v1 头、加密参数、CRT 系数和填充规则等。文中还配有大量十六进制分解示例和注释，帮助读者理解每个字节的含义。文章特别指出，纯文本密钥的 cipher 和 KDF 字段均为 "none"，且缺乏 KDF 选项；并建议使用 RSA 时优先选择 4096 位。整体上，这是一份面向开发者和安全研究人员的底层密钥格式参考手册。

## 10. 自动化的若干道德与技术后果

- 原始链接: <https://www.cs.umd.edu/users/gasarch/BLOGPAPERS/moral.pdf>
- 英文标题: Some Moral and Technical Consequences of Automation (1960)

本文是控制论创始人诺伯特·维纳于1960年发表的经典论述，旨在探讨自动化技术发展所引发的道德与技术层面的深层后果。维纳指出，第二次工业革命的核心特征并非简单的体力替代，而是机器开始具备学习、决策和优化等智能行为。他警告，当机器能够在复杂环境中自主选择路径并快速行动时，人类可能无法完全预见其行为后果，从而使道德责任变得模糊和危险。文章强调，自动化的真正威胁不在于机器本身，而在于人类在赋予机器目标时的粗心与短视——若我们向机器输入的目标与人类真实意图存在偏差，机器将以其高效和精确的方式放大这一错误，造成难以挽回的损失。维纳还讨论了自动化可能导致的失业、社会不平等以及人类对自身智能的过度自信等问题。他提出，机器学习虽能模仿某些认知过程，但绝非万能，人类必须正视自身在技术责任上的局限。总体而言，本文既是对自动化前景的冷静分析，也是对科技发展中人性和道德责任的深刻警醒，对后来的技术伦理研究具有奠基性影响。

## 12. Rust 夜间版启用下一代借用检查器 Polonius Alpha

Rust 团队宣布在 nightly 版本中启用下一代借用检查器“Polonius Alpha”，为未来数月内的稳定化做准备。该检查器源自 2018 年的 Polonius 项目，早期实现因性能问题未能落地。2023 年新 formulation 在 NLL 基础上实现最小重构，并支持流敏感分析。与现有 NLL 相比，Polonius Alpha 能接受更多合法代码，例如在 match 分支中提前结束借用，允许 get_mut_or_default 这类模式编译通过。但它并非完美，部分旧 Polonius 能编译的代码目前不被支持，也发现了一些反例。性能方面，在 crates.io 下载量前一万的 crate 中，绝大多数无明显回归，少数显著回归通常也较小；最坏情况约 2-3 倍变慢。用户可通过 -Zpolonius=off 或 .cargo/config.toml 关闭。团队将在未来几个月收集问题、优化性能并完善文档，目标在年底前稳定化。稳定后暂不计划继续添加新功能，但会持续优化性能。

## 13. Systemd 动态用户（2020）

- 原始链接: <https://ethulhu.co.uk/systemd-dynamicuser>
- 英文标题: Systemd Dynamic Users (2020)

本文介绍了 systemd 的动态用户（Dynamic Users）功能。传统上，Linux 创建用户需写入 /etc/passwd 和 /etc/group，而 systemd 可在单元（Unit）运行期间临时创建用户，该用户不进入系统数据库，仅存在于运行时，单元结束后自动消失。此类用户权限默认受限，但仍是完整的 Linux 用户，可加入组、写入磁盘或赋予能力。配合 StateDirectory 机制，动态用户可持久化写入指定目录，并在下次运行时自动修复属主，适合存储服务数据或模拟家目录。

动态用户的核心价值在于简化服务打包与运行：无需在安装时创建系统用户、卸载时删除，服务包只需安装单元文件即可。文中以作者自建 Web 服务 log.eth.moe 为例，展示了 DynamicUser=yes、Group=www-data、RuntimeDirectory 和 StateDirectory 的配置。另一个例子是在树莓派上通过动态用户运行 Kodi，设为 User=kodi 并补充 audio、video 等组，StateDirectory 指向 /var/lib/kodi，配合 HOME 环境变量实现媒体中心。

文章还演示了利用 systemd-run 动态用户沙箱运行 Steam：创建 eth-x11 组并通过 xhost 授予显示权限，脚本使用 DynamicUser、Group、SupplementaryGroups、StateDirectory 等属性，将 Steam 隔离在临时用户中，同时保留音频、输入、显示等必要访问，实现了轻量沙箱。作者指出 systemd-run 需要 root 或认证，可用 sudoers 或 setuid 改善体验。

## 17. Shell 感叹号不是用来喊叫的：做个懒人

- 原始链接: <https://refp.se/articles/your-shell-and-the-lazy-exclamation-mark>
- 英文标题: A shell exclamation mark is not for yelling. Be lazy

这篇文章介绍了 shell 中常被忽视却功能强大的事件设计符（event designators），帮助用户快速复用历史命令、节省击键。作者首先点明程序员都是“懒惰”的，而感叹号正是为这种懒惰服务的工具。文章详细解释了事件设计符的基本语法 `![event][:word][:modifier]`，并分别介绍了三个组成部分：事件设计符用于选择历史行，如 `!!` 重复上一条命令、`!ssh` 匹配最近以 ssh 开头的命令、`!?dandelion?` 匹配包含指定内容的命令；单词设计符用于抽取命令中的特定部分，如 `!$` 取最后一个参数、`!:0` 取命令本身、`!:2*` 取从第三个到最后一个参数；修饰符则用于进一步处理，如 `:h` 取目录、`:t` 取文件名、`:r` 去除扩展名、`:s/foo/bar/` 做替换。文章还介绍了 POSIX 的 `fc` 命令，它允许在外部编辑器中编辑历史命令再执行，并支持批量替换。作者给出了核心推荐，包括“三规则”（`!!`、`!needle`、`!?needle?`）和“强大四”（`!$`、`!:0`、`!$:h`、`!$:t`）。同时提醒这些技巧仅适用于交互式 shell，不可用于脚本；并建议使用 `histverify` 或 `HIST_VERIFY` 先展开验证，也可在不需要时通过 `set +H`、`setopt nobanghist` 或自定义 `histchars` 关闭。整体而言，这是一篇实用性强、操作示例丰富的命令行效率指南。
