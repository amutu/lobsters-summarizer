## 1. 改变我世界的十行代码

- 原始链接: <https://pixelambacht.nl/2026/ten-lines-of-code/>
- 英文标题: Ten Lines Of Code That Changed My World

本文是作者以怀旧视角回顾编程生涯的随笔，精选十段对其有特殊意义的代码片段。从BASIC语言的「Hello World」死循环，到JavaScript中经典的Array(16).join('wat'-1)+'Batman'梗；从6502自修改汇编展示机器码可覆写自身，到Windows批处理touch.bat模拟Linux的touch命令；从CSS调试用的「border:10px solid hotpink」，到游戏作弊码POKE 9450,173；从用空循环假装性能优化的职场幽默，到Linux IRC上「rm -rf /」的经典玩笑；从90年代用Borland Pascal编写的粗糙用户名扫描器SKAN2.PAS，到受Twitter 280字符限制启发的纯CSS动画诗。每段代码都承载特定时代记忆，串联起作者从BASIC入门到现代Web开发的完整历程。文章基调轻松幽默，兼具技术趣味与个人情感，核心亮点在于用极简代码片段折射出编程文化的演变与开发者群体的集体记忆，读来既像技术笔记，也像一封写给旧时光的情书。

## 2. 停用AI一个月：一位开发者的清醒与回归

- 原始链接: <https://blog.bustikiller.com/2026/09/25/one-month-without-ai.html>
- 英文标题: One month without AI

作者维护开源项目LibreWeddingPlanner，数月前提出不接受AI贡献，但工作中仍深度依赖AI编码。他描述了从启用自动补全到让AI代理实现整个Jira工单、多agent并行工作的失控过程：TDD意义被架空，AI甚至代签commit；多agent并行导致注意力严重分散，原本20分钟的任务需两天才能审完；AI代码质量逐渐下滑，需反复指导如同带实习生；agent卡住30分钟后用严厉语气催促竟20秒完成，却消耗30美元token。转折发生在一场代码评审中，同事指出AI所写测试并未覆盖实际变更场景，作者深感羞耻，意识到自己已丧失对代码的理解与控制。他决定彻底停用AI，即使面临失业风险。回归后，他重拾TDD、小范围PR、简洁描述、人类评审与架构讨论，重新获得编程乐趣。他坦言停用后并未降低产出，反而对代码更熟悉、更能应对线上事故、技术能力持续提升。文章最后呼吁开发者警惕AI依赖，保持大脑活跃，因为工程师的核心价值在于自身能力，而非充当「AI牧羊人」；同时提醒企业AI预算终将收紧，提前回归自主编程是更稳妥的选择。

## 3. postmarketOS 正式更名为 Nura

- 原始链接: <https://nura.eco/blog/2026/09/27/nura-rename/>
- 英文标题: postmarketOS rebrands as Nura

经过一年半的社区筛选流程，开源操作系统 postmarketOS 在其年度会议的特别环节上正式宣布更名为 Nura。Nura 取自意大利撒丁岛上公元前 3000 年的花岗岩古堡 Nuraghe，寓意历经千年仍屹立不倒的稳定性，与项目让旧设备长期可用的核心理念高度契合。改名由社区成员 Davide Depau 提议。团队解释，原名 postmarketOS 存在诸多问题：名称冗长、多语言下难以发音和记忆、大小写不规范导致拼写混乱、描述性命名限制了项目边界（例如 PINE64 预装该系统的 PinePhone 案例），且无法注册商标以保护用户免受仿冒。新名称由 Pablo、Pan、Ranny 和 Sriram Ramkrishna 组成的评审小组从 300 余条社区提案中经多轮筛选、跨语言歧义排查后，以区间投票（range voting）方式最终选出。项目同时选择 Nura.eco 作为新域名，因 Nura.org 已被占用且无法以合理价格购得，而 .eco 域名强调环保承诺，与项目使命相符。标志整体保留，仅对箭头间距等细节做了微调以提升可读性。团队表示，所有面向用户的字符串替换尚需时间，欢迎社区提交合并请求协助更新。

## 4. LuaRocks.org 2026年9月安全事件：远程代码执行漏洞披露与响应

- 原始链接: <https://luarocks.org/security-incident-september-2026>
- 英文标题: LuaRocks Security Incident September 2026

2026年9月25日，LuaRocks.org经CISA协调收到远程代码执行漏洞报告，9月26日完成修复。调查发现该漏洞在7月9日至8月20日期间已被攻击者多次利用。漏洞根源在于：站点运行于OpenResty（LuaJIT），rockspec解析器用loadstring加载用户上传文件时未限定仅接受文本模式。Lua 5.1和LuaJIT中loadstring默认同时接受源码与预编译字节码，攻击者可上传恶意字节码绕过空环境沙箱，访问任意内存并调用被隐藏函数，实现服务器进程内任意代码执行。修复方案为向loadstring传入「t」模式并拒绝以\27开头的文件。因攻击者获得服务器完全控制权，所有API密钥、会话、2FA密钥及GitHub令牌均已吊销，站点迁移至全新服务器。经每日git镜像对比，未发现现有包被篡改，三个恶意包（bcrcewon等）已移除。用户需创建新密钥、重置密码、重新配置2FA，并升级至LuaRocks 3.12及以上版本，尤其LuaJIT和Lua 5.1用户。

## 5. 去垃圾化（二）：绕过应用商店的守门机制

- 原始链接: <https://fabricati-diem.inform.social/post/deshittification-as-a-service-part2-bypassing-the-app-store-gatekeeper/>
- 英文标题: Deshittification Part 2: Bypassing the App Store Gatekeeper

本文是Lari Huttunen「去垃圾化」系列第二篇，记录其将LG OLED WebOS电视置于隔离VLAN、经OpenBSD网关与Unbound DNS屏蔽LG遥测及广告域名后的对抗实验。屏蔽后，WebOS并非静默丢弃遥测包，而是主动锁定应用商店并抛出错误码E5.48.XV，而浏览器与本地应用均正常。作者通过DNS日志发现，电视在打开商店前会强制解析LG追踪域名wiselg.com，解析失败即中止整个商店流程，根本不尝试连接应用CDN，证明该锁定纯属人为守门。临时放行追踪域名两分钟，商店立即恢复，Netflix成功安装并播放4K；重新屏蔽后商店再次锁定，但已安装的Netflix仍可短暂播放，证实第三方流媒体对LG追踪服务器零技术依赖。作者据此援引GDPR第7(4)条「自由同意」原则，认定LG以基础功能要挟数据收集构成强制同意，并向LG数据保护官提交正式投诉。文章末尾揭示冷启动时WebOS会向第三方应用发送大量TCP RST包破坏加密连接，预告第三篇将深入分析该网络破坏机制，并呼吁用户自行抓包、截图取证，为监管机构提供可执行的法律依据。

## 6. 逆向工程 iPod Classic 未文档化的 Mikey 芯片，实现耳机线控支持

- 原始链接: <https://terminalbytes.com/reverse-engineering-ipod-classic-mikey-chip/>
- 英文标题: Reverse Engineering the iPod Classic's Undocumented Mikey Chip

作者为运行 Rockbox 固件的 iPod Classic（7代）实现了 Apple 有线耳机线控的完整支持。核心难点在于解码耳机接口的 Mikey 芯片（I2C 地址 0x72），该芯片无任何公开文档，唯一参考是16年前一篇已失效的博客，幸而通过 wiki 镜像找回。作者在设备内构建调试界面，将模式寄存器全部256个值逐一扫描，最终发现写入 0x2f 可启用按钮事件报告。线控按钮实为模拟信号：中键是麦克风线短路，音量键为不同阻值负载，芯片仅做电平检测。然而硬件存在缺陷——事件引擎约5秒无操作后休眠，释放事件延迟约1.8秒才上报，导致中键无法可靠报告按压时长，最终只能实现单击。驱动已提交至 Rockbox 上游 Gerrit 审查（change 7677），作者同时发布了预编译镜像 ipod6g-mikey-v1，支持6代和7代 iPod。此外还附带了浏览器端启动 logo 替换小工具。

## 7. 现代网站的正确姿势：回归纯HTML，拒绝过度工程化

- 原始链接: <https://modernmotherfuckingwebsite.dreamstation.systems/>
- 英文标题: This is a modern motherfucking website

本文以极其激烈的语气痛批当代Web开发中的过度工程化，主张绝大多数所谓「现代功能」无需框架、打包器或Node.js工具链，纯HTML即可实现。作者逐一论证：语义化标签（nav、article、main等）天然支持无障碍与SEO；<details>、<dialog>等原生元素可替代组件库；JSON-LD结构化数据仅在head中嵌入一段JSON；Open Graph社交卡片不过是七个meta标签；资源提示（preconnect、preload、fetchpriority）与推测规则（speculation rules）一行代码即可优化性能与导航体验；<picture>标签配合AVIF/WebP实现响应式图片，浏览器自动选取格式；暗色模式一个media query，响应式布局一个max-width。作者强调这些均为浏览器平台原生能力，框架至多提供更慢的写法，甚至将免费能力藏入插件生态让人遗忘。该演示页面本身仅约23KB、零依赖、部署即复制文件。对于多页面站点，静态生成器足矣；真正的应用场景才需要框架。核心方法论：从HTML起步，按需添加，完成即止。

## 8. 在 p5.js 中教授 GPU 编程：现已支持计算着色器

- 原始链接: <https://www.davepagurek.com/blog/p5-compute-shaders/>
- 英文标题: Teaching GPU programming in p5.js: now with compute shaders

本文讨论了计算机图形学教育面临的困境：GPU 已远超「图形」范畴，成为通用并行计算平台，但学习门槛极高（如用 Vulkan 渲染一个三角形需数千行代码）。作者提出「脚手架学习」理念——先隐藏底层管线细节，让学习者逐步接触。作为 p5.js 核心开发者，作者介绍了 p5.strands 着色器系统的教学设计：已有 p5.js 基础的学习者无需了解着色器管线、uniforms 等概念，即可从自定义滤镜（filterColor）起步，逐步过渡到用 texCoord 做渐变与噪声纹理、用 millis() 驱动动画、用 uniformFloat 接入滑块参数。随后扩展到对 3D 物体顶点施加变换（worldInputs）、实例化渲染（buildGeometry 配合 model 批量绘制），再到 WebGPU 存储缓冲区（createStorage / uniformStorage）承载粒子数据，甚至可从 SVG 路径提取坐标。最终引入计算着色器（buildComputeShader），将传统 for 循环的粒子状态更新（如弹球）转为 GPU 并行执行，为自主体模拟等场景提供教学入口。文章强调抽象应便利直观但不误导，学习者无需「反学」即可平滑过渡到工程级系统。

## 9. 在 Linode 上部署 Guix 镜像

- 原始链接: <https://dthompson.us/posts/deploying-guix-images-on-linode.html>
- 英文标题: Deploying Guix images on Linode

作者因 Digital Ocean 向争议项目 Omarchy 捐款而迁移至 Linode，并分享了直接在 Linode 上部署 Guix 系统镜像的方法，而非 Guix Cookbook 中从 Debian 镜像转换的方案。其 Guix 操作系统配置涵盖：支持 virtio_scsi 虚拟磁盘、启动时自动扩展根文件系统（因 Guix 自带 resize-file-system-service 不适用而自定义 shepherd 服务）、仅公钥认证的 SSH、免密码 sudo 以支持 guix deploy、将 GRUB 安装至根文件系统而非引导设备、通过 SLAAC 获取 IPv6 地址，以及 nftables 防火墙。镜像生成方面，作者用 guix system image 的 mbr-raw 类型生成原始镜像，再用 dd 跳过前 1048576 字节的 MBR 区域仅保留根分区，最后 gzip 压缩后上传。上传后需在 Linode 配置中选择「GRUB 2」内核并关闭所有文件系统与启动辅助开关，否则实例将内核恐慌。完成配置后可通过 SSH 使用 guix deploy 进行系统更新。完整代码已发布于 Git 仓库，作者表示暂无精力更新 Guix Cookbook，希望此博文暂作参考。
