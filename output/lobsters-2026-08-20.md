## 1. HTML也能做到

- 原始链接: <https://chrisburnell.com/html-can-do-that/>
- 英文标题: HTML Can Do That

文章介绍HTML正不断接管原本属于JavaScript的职责，列举了当下可直接用纯HTML实现的动态功能，并标注了各功能的浏览器兼容性。关键亮点包括：<dialog>元素配合command和commandfor属性，仅用HTML即可打开和关闭模态对话框；popover属性实现轻量弹出层，支持点击外部和Esc键关闭，无需手动管理z-index；为多个<details>设置相同的name属性，可形成互斥手风琴，打开一个自动关闭其他。command/commandfor还可控制popover显示与隐藏，目前浏览器已稳定支持show-modal、toggle-popover等命令，未来有望扩展至增减数值、控制媒体元素等。此外，原生color、range、date输入选择器以及datalist原生的自动补全功能，省去了引入下拉库的麻烦；img的loading="lazy"实现图片延迟加载，无需IntersectionObserver；hidden="until-found"结合页面片段导航，可在用户跳转时自动显示隐藏内容。文章强调这些HTML新特性能在很多场景下减少对JavaScript的依赖，同时提醒读者留意不同功能的浏览器支持情况。

- 英文标题: Bun 1.4 Rust rewrite is not looking good

## 3. 为什么我仍然手写Git提交信息

- 原始链接: <https://www.jvt.me/posts/2026/08/17/hand-write-commits/>
- 英文标题: Why I still hand write my commit messages

作者Jamie Tanna在文中解释了自己坚持手写Git提交信息的原因，即使在LLM可以代写的时代。核心观点是：提交信息应侧重解释“为什么”而非“什么”，因为diff已经展示了变更内容，而“为什么”提供了关键上下文。他还会在信息中说明前置重构、bug修复背景、自身失误、权衡取舍等细节。手写提交信息的过程也帮助他检验自己是否真正理解变更，类似“教学相长”；有时在撰写时会发现自己原本的选择不合适，或发现更好的方案。对AI辅助代码而言，手写提交信息也是承担责任和所有权的方式，他还会在原子提交中明确标注哪些部分由AI协助。作者承认AI无法完全复制他的个人风格，但他用Claude Max配合专门创建的技能，为不太重要的项目生成接近自己风格的提交信息。此外，他本身热爱文档写作，认为提交信息是重要文档的一部分。最后他说明这仅是他个人的工作方式，不强迫别人效仿，并且写作耗神，自己有时也没有精力完成。文中还附了多个实际提交示例，展示如何写出“为什么”、前置重构、bug修复、安全变更及AI归属等。

## 4. 纯文本会计：很酷的记账方式

- 原始链接: <https://sumnerevans.com/posts/money/plain-text-accounting/>
- 英文标题: Plain Text Accounting is Pretty Cool

作者长期热衷记录个人财务，先后使用Mint、Rocket Money和Origin等工具，但因账户连接不稳定、无法处理已关闭账户、无法将401(k)扣除计入储蓄率等问题，最终决定转向纯文本会计（PTA）。文章中，作者介绍了纯文本会计的概念——用纯文本文件存储账目，并搭配工具（如hledger）进行记账和报告。作者选择hledger，因为它用Haskell编写、社区支持好、支持CSV导入、日记文件格式简洁。文章重点展示了hledger的几个实用功能：支持多账户交易（如亚马逊订单混合礼品卡、奖励和信用卡支付）；可跟踪股票等商品及价格信息；支持将日记拆分为多个文件并按账户管理；通过权益转账账户跟踪银行转账在途资金；用应收账户处理可报销费用，避免工作支出被记为费用；余额断言可核对账户余额并发现错误。此外，hledger还支持CSV规则导入、register命令、check校验和Web界面。作者表示刚使用几周，虽需手动录入每笔交易，但复式记账带来的严谨性让其觉得值得，并推荐给同样关注每一分钱并喜欢纯文本存储财务数据的人。

## 5. Go 1.27 正式发布

- 原始链接: <https://go.dev/blog/go1.27>
- 英文标题: Go 1.27 is released

Go 团队于2026年8月19日发布Go 1.27，带来语言、工具链、运行时和标准库的多项重大改进。语言方面，新增泛型方法支持，math/rand/v2.Rand 中可通过一个通用方法处理所有整数类型；结构体字面量允许直接使用嵌套或内嵌字段作为键进行初始化；函数类型推断扩展到所有赋值场景，可在复合字面量、类型转换和通道发送中省略显式类型参数。工具链上，go fix 新增 atomictypes、embedlit、slicesbackward、unsafefuncs 等现代化改写；go doc 支持 package@version 查询；go mod tidy 自动合并多个 require 块为标准结构。性能和运行时方面，按大小优化的内存分配使小于80字节的小对象分配成本降低最多30%，分配密集型程序整体性能提升约1%；runtime/pprof 的 goroutineleak 分析现已正式可用，可自动检测永久阻塞的 goroutine。标准库新增 encoding/json/v2（提供可配置的高层 JSON 处理）及底层 jsontext 包，现有 encoding/json 改用 v2 实现以提升反序列化速度并保持兼容；crypto/mldsa 实现后量子签名方案 ML-DSA（FIPS 204），并集成到 crypto/x509 和 crypto/tls；新增 uuid 包原生支持 UUID 生成与解析；simd 和 simd/archsimd 提供实验性 SIMD 支持；net/http/httptest 新增 NewTestServer，提供适合与 testing/synctest 配合使用的内存假网络。完整变更见官方发布说明。

## 6. SQLite 适用于一切

- 原始链接: <https://joecode.com/2026-08-19-sqlite3/>
- 英文标题: SQLite for Everything

这篇文章以戏仿《PostgreSQL for Everything》的口吻，论证 SQLite 这个常被视为玩具的嵌入式数据库才是“万金油”。作者认为 SQLite 的强大源于三点：稳定性极佳（2000年发布，公共领域，测试采用航空级标准，支持承诺到2050年）；运行、安装、扩展都异常简单（内核自带、可内存运行、支持 Litestream 等复制工具）；能大幅简化 IT 架构。文章用大量实例展示 SQLite 能替换其他系统：FTS5 替代 Solr/Elastic 做全文搜索；JSON 和 jsonb 功能替代 MongoDB；事务和 RETURNING 实现队列，替代 Kafka/RabbitMQ；按文件分区和批量写处理时间序列数据，替代 Clickhouse；sqlite-vec 扩展成为向量数据库；还能作为缓存替代 Redis，以 BLOB 替代文件系统，用递归 CTE 替代图数据库，甚至把查询变成函数调用替代微服务。作者承认 SQLite 有单写者和单机上限，但认为多数场景下足以应对，简单性才是快速交付的关键。文章结论是：SQLite 未必能回答一切，但它的适用面远超你想象，而且已经装好了。

## 8. MicroLighter：基于 CSS Custom Highlights API 的轻量级语法高亮器

- 原始链接: <https://daverupert.com/2026/08/microlighter/>
- 英文标题: Introducing Microlighter

MicroLighter 是一个作者新开发的客户端语法高亮库，核心特点是零依赖、压缩后仅约 2KB，利用 CSS Custom Highlights API 而非传统的 span 标签注入来实现高亮，从而避免 DOM 修改。它采用 Textmate 语言语法（即 VS Code 所用的语法集合），因此能支持几乎所有语言，且所有语言语法按需自动加载，减少配置和包体积。作者将 Textmate 细粒度标记类别简化为人性化的一组 token（如注释、关键字、字符串等），并利用 CSS 的 light-dark() 函数将亮色和暗色主题合并为单一主题，简化了主题管理。库本身只负责语言推断和高亮，额外的功能（如行号、复制按钮等）被封装到一个 <micro-lighter> 自定义元素中（约 1KB），作者认为这种组件化方式能更好地分离关注点。文章还介绍了安装和使用方式：既可通过自初始化压缩脚本简单调用，也可通过 ESM 引入 highlightAll，或使用自定义元素获得增强功能；主题可通过定义 --syntax-* 变量进行自定义。最后作者提到欢迎试用并反馈意见。不足之处：原文未详细说明浏览器兼容性，总结中也未提。整体而言，MicroLighter 为语法高亮提供了一种轻量、无 DOM 干扰且主题友好的新方案。

## 9. SoLo：为静态Linux二进制文件打造的.so加载器

- 原始链接: <https://github.com/pg83/solo>
- 英文标题: Solo: a .so loader for static Linux binaries

SoLo是一个面向完全静态Linux可执行文件的共享库加载器。通常，使用musl构建的静态二进制文件无法通过dlopen加载系统提供的glibc链接的GPU驱动（如Vulkan/OpenGL），而SoLo解决了这一难题。它自带ELF加载器（支持x86-64和aarch64），并在musl运行时之上实现了glibc ABI桥接，使静态链接的应用程序能在运行时直接使用主机上已安装的图形驱动，无需容器、AppImage或引入第二个libc。文章提供了端到端的Vulkan演示：一个完全静态的可执行文件加载主机未修改的Vulkan驱动，运行计算着色器并输出PNG，已在AMD、Intel、NVIDIA及Asahi Linux的Apple M1上测试。此外，CI每次提交都会在两种架构上加载Debian最常安装的1000个包中所有共享库（约2100个对象）以验证兼容性。SoLo支持四种TLS模型、符号版本化、IFUNC、RELRO等，并对未实现的glibc函数生成显式失败桩。与Detour、Cosmopolitan、ClickHouse等方案不同，SoLo全程只保留一个musl运行时，且允许将静态可执行文件中已有的符号（如libwayland）提供给加载的DSO。项目旨在将“完全静态”与“使用系统GPU”之间的硬墙变为有限且可测试的兼容层。

## 10. curl 8.10.0 新特性：当 URL 中没有文件名时如何命名本地文件

- 原始链接: <https://daniel.haxx.se/blog/2024/08/19/a-filename-when-none-exists/>
- 英文标题: a filename when none exists

本文是作者关于即将发布的 curl 8.10.0 新功能迷你系列的第四集，重点介绍命令行选项 -O（--remote-name）的改进。此前，-O 会从 URL 的文件名部分创建本地文件，例如 `curl -O https://example.com/file.html` 会保存为 file.html。但遇到没有文件名部分的 URL（如 `http://example.com/`、`http://example.com/path/` 或带查询参数的地址）时，curl 会因为没有可用的本地文件名而报错。从 8.10.0 起，curl 会尝试额外步骤：若 URL 中有文件名则照旧；若无文件名但有路径，则取 URL 中最右侧的目录名作为文件名，例如 `http://example.com/one/two/?id=42` 会保存为 `two`；若既无文件名也无路径，则使用固定默认名 `curl_response`，该名称故意不带扩展名，以免误导用户猜测内容类型。作者还回应了用 `index.html` 作为默认名的建议，认为那样更可能误导人。用户可以通过 `-w %{filename_effective}` 查看实际使用的文件名，也可用 `-o` 自行指定。此外，curl 默认会覆盖同名文件，若想避免覆盖可使用 `--no-clobber` 选项。文章通过表格展示了不同 URL 对应的本地文件名示例。

## 11. Go 1.27 版本发布说明

- 原始链接: <https://go.dev/doc/go1.27>
- 英文标题: Go 1.27 Release Notes

Go 1.27 于 2026 年 8 月发布，保持了 Go 1 兼容性承诺。语言方面最重大的变化是支持泛型方法，即方法声明可拥有自己的类型参数，例如 math/rand/v2 新增了 (*Rand).N 泛型方法；结构体字面量中的键可以是任意合法字段选择器；函数类型推断已推广到泛型函数赋值或转换的所有上下文。工具链方面，compile、link 等工具支持 @file 响应文件，go 命令不再支持 bzr 版本控制，GODEBUG 对已移除设置的新处理方式，go test 默认启用 stdversion 检查，go doc 支持 package@version 语法。运行时方面，编译器针对小型（<80字节）内存分配生成专用调用，性能最高提升 30%，整体约 1%；新增 goroutine 泄漏分析 profile，现已在 runtime/pprof 和 net/http/pprof 中正式可用。编译器对 //line 指令、闭包命名进行了改进。标准库新增了 encoding/json/v2（更严格、更快的 JSON 实现）、crypto/mldsa（FIPS 204 后量子签名）、uuid 包，以及实验性 simd 和 simd/archsimd 包。此外，compress/flate 压缩速度提升，crypto/tls 支持 ML-KEM1024 密钥交换和 ML-DSA 签名，crypto/x509 支持 ML-DSA 密钥等。多个过时的 GODEBUG 设置被永久移除。

## 12. 我对现代关系查询语言的期望

- 原始链接: <https://sporks.space/2026/08/19/things-i-want-in-a-modern-relational-query-language/>

## 23. 关于构建编译器的看法

- 原始链接: <https://programmingsimplicity.substack.com/p/opinions-about-compiler-building>
- 英文标题: Opinions About Compiler Building

本文作者Paul Tarvydas基于30多年的软件咨询经验，分享了他对21世纪构建编译器的个人观点。作者首先区分了语言设计与编译器构建：他认为当今世界已拥有足够的编译器，应避免重复构建，但新语言仍有发展空间。他建议先快速原型化语言，使用OhmJS（基于PEG技术的解析器生成器）和Ohm-editor来辅助编写语法并查看解析树，并指出将语法写两遍比一开始就陷入实现细节更高效。他认为解析器是编译器中最容易的部分，真正的难点在于类型检查，建议用关系编程（如Prolog）来表达类型规则，并使用三元组和数据描述符简化数据表示。在代码生成上，他主张先输出“笨拙”的代码，再用peephole优化；整体采用Unix风格的管道式多阶段架构，分别使用适合解析、类型检查和可移植性的工具。他还建议先为语言编写解释器，再考虑编译优化；认为JavaScript或Lisp是较好的中间表示，而LLVM过于复杂。文章最后介绍了他自己的PBP（基于部件的编程）工具集，包括T2T转换器、FDD LLM工具等，并附有大量参考链接。总体而言，作者强调在现代工具环境下，应摒弃20世纪的陈旧编译器构建思路，追求更简单、更高效的设计方法。
