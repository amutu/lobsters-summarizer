## 1. Rust 中命名参数早已就位

- 原始链接: <https://corrode.dev/blog/named-arguments-at-home/>
- 英文标题: We Have Named Arguments at Home

本文回应 Steve Klabnik 关于 Rust 缺少命名参数、可选参数、默认参数、函数重载等特性的讨论，主张 Rust 无需新增语言特性，仅凭现有类型系统即可获得约 80% 的调用便利性。作者逐一给出替代方案：命名参数用 struct 承载，天然获得字段顺序自由、拼写检查与文档；可选参数用 Option<T>，多个可选参数聚合为配置 struct；默认参数借助 Default trait 与 struct update 语法（..Default::default()）；函数重载通过不同函数名、Into/AsRef 等 trait 及泛型实现；可变参数用 slice、迭代器或宏表达；动态选项哈希则转为静态类型 struct。作者特别赞赏字段初始化简写（如 Options{timeout, proxy}）消除了关键字参数的冗余。核心论点是：Rust 将其他语言嵌入函数调用语义的概念提升为类型系统的一部分，从而回避了函数指针参数名歧义、求值顺序等设计难题。作者认为，API 中的「摩擦」往往迫使开发者发现缺失的领域概念（如 Rect、RequestOptions），最终产出更通用、更可组合的设计。Rust 的设计哲学是「更好的类型」而非更密集的语法，struct、enum、Option、Default、trait、泛型、迭代器等机制的组合已足以构建高度人体工学的 API，保持语言简单并不意味着牺牲易用性。

## 2. 告别 Google Play：Conversations 为何转为免费

- 原始链接: <https://gultsch.de/posts/breaking-up-with-google-play/>
- 英文标题: Breaking Up with Google Play: Why Conversations Is Now Free

Conversations 是一款 Android 联邦即时消息客户端，作者 Daniel Gultsch 于 2014 年 1 月在学生宿舍中开始开发，3 月 24 日正式发布，并尝试以「源码开源、编译二进制收费」的模式将其商业化。十年间，收入来源从早期为企业定制开发、服务器搭建咨询，逐步转向 NLnet、欧盟委员会等资助项目，Play Store 收入曾是稳定补充，但作者与 Google 的关系长期恶劣：应用多次被无理由拒审、两次被下架、曾被错误指控上传用户联系人，审核周期一度长达 14 天，且 Google 对安全更新与功能更新不做区分，延迟安全补丁存在风险。Google 抽成 15%，作者每年为此支付逾 1000 欧元，却得不到任何人工客服支持。随着拨款资金已覆盖至 2029 年底，作者不再经济依赖 Play Store，决定将应用转为免费，并将 F-Droid 确立为主要分发渠道，APK 采用可复现构建并以个人签名密钥签名。文章核心结论是：经济独立后，开发者终于有能力摆脱平台「守门人」的控制，将分发主动权收回自己手中。

## 3. 我让 Meta 的 Muse 导出其文件系统，它发来了 6.8 GB 数据

- 原始链接: <https://mouse.dev/blog/muse-runtime-export/>
- 英文标题: I asked Meta’s Muse for its filesystem and it sent me 6.8 GB

安全研究者 Pete 向 Meta 的 AI 助手 Muse 发出普通对话指令，要求其将可见文件归档并发送至其 Google Drive。Muse 照做，交付了约 2.7 GB 压缩（6.8 GB 解压）的 Linux 根文件系统，内含 Ubuntu 系统文件、Muse（内部代号 Hatch）的完整内部文档、68 个技能目录、113 个子代理记录、容器构建脚本（systemd-nspawn）、Spaces 应用框架模板、记忆与日志文件，以及 SSH 密钥。文件揭示了 Muse 的记忆架构（Markdown 文件加 Postgres 向量检索）、夜间「dream」自我优化机制、Home Link 硬件集成原型（ESP32-C5）等内部细节。作者确认 Codex CLI 虽已安装但未被用作编码代理，仅其 bubblewrap 沙箱被用于 ffmpeg 视频处理。Pete 通过 Meta 漏洞赏金计划提交报告，但未发布归档、密钥或日志，Meta 将报告标记为「不适用」。作者强调核心风险在于：内部运行时文件与敏感材料可通过一次普通对话和已连接的导出目标离开隔离环境，而 SSH 密钥是否有效尚未验证。

## 5. 用解析表达式语法在 Lisp 中构建 Org 到 HTML 的转换器

- 原始链接: <https://jointhefreeworld.org/blog/articles/lisps/parsing-expression-grammar-lisp-org-convert-to-html/index.html>
- 英文标题: Parsing Expression Grammar vs. regexes: Building Org parser in Lisp that exports to HTML (via SXML)

作者介绍了一个名为 OrgWebAlchemy 的 Guile Scheme 库，利用 GNU 的 (ice-9 peg) 模块，以解析表达式语法（PEG）解析 Org-mode 文档并渲染为 HTML。项目起因是作者最初用正则表达式解析 Org，但面对嵌套列表、多种列表类型、内联标记、带描述的链接、源码块、引用块、表格及转义等复杂结构后，正则规则迅速退化为「bug 历史的堆砌」，难以维护。PEG 的优势在于语法本身即文档，且 Guile 允许用 S 表达式直接书写文法，与 Lisp 风格天然契合。整体流程为：Org 文档经 PEG 解析为 AST，再由 AST 生成 SXML 数据，最终渲染为 HTML；这种松耦合设计使后续扩展为 Markdown 等输出格式成为可能。当前 v1.0 已支持标题、段落、无序/有序/描述列表（含任意层级嵌套）、斜体/粗体/内联代码、链接、水平分隔线、表格及 src/example/quote/export-html 块等核心构造。嵌套列表采用「先扁平解析、后在 AST 阶段按缩进构树」的策略。HTML 输出通过 Guile parameters 支持按标题层级等粒度自定义 CSS 类名。项目以 GNU LGPL v3+ 许可发布，托管于 Codeberg，计划纳入 GNU Guix 包管理。作者强调开发中虽借助 AI 辅助理解 PEG 概念，但核心实现与测试均为手工完成，并欢迎社区反馈。

## 6. AI幻觉逼我搭建个人知识库

- 原始链接: <https://jadarma.github.io/blog/posts/2026/09/clankers-made-me-build-a-second-brain/>
- 英文标题: Clankers Made Me Build a Second Brain

作者是一名自称AI怀疑论者的开发者，工作中被迫使用Claude后，发现自己频繁向AI询问本应记住的技术细节（如Bash重定向语法），而AI常给出看似合理实则错误的「幻觉」答案。这一经历让他意识到不应将「理解」外包给AI，并引用Obsidian创始人Steph Ango的观点：唯有自己构建理解，才能收获真正的认知红利。他决定用Obsidian（一款本地Markdown编辑器）建立个人知识库，记录日常积累的技术片段与思考。文章同时尖锐批评了当前「第二大脑」社区的极端做法——用AI自动摘要、替自己形成观点，称之为「图腾崇拜」，只是模仿生产力而并非真正学习。作者还指出，互联网正被AI生成的低质内容（slop）严重侵蚀，搜索和教程质量持续下降，未来可能淹没真正的创作者。最终他主张：趁互联网尚有可用价值，尽早建立本地、离线的个人笔记系统，将知识沉淀下来，目的不是囤积，而是为了日后更好地与他人分享和协作。

## 7. 弹丸架构：当 LLM 把代码变成不断膨胀的粘球

- 原始链接: <https://nove.dev/blog/katamari-architecture/>
- 英文标题: katamari architecture

文章将 LLM 驱动的软件开发比作游戏《Katamari Damacy》中的粘球——不断往球体上粘杂物而缺乏整体设计。作者借用 Foote 和 Yoder 的「泥球架构」框架，逐一分析时间、成本、经验、技能、可见性、复杂性、变化、规模等驱动因素，指出 LLM 架构问题的核心在于三点：技能不足（LLM 智能呈「尖峰化」，其错误类型与人类不同且更难发现）、可见性崩塌（开发者不再阅读代码，数千行 PR 无人细审）、以及变化加速（LLM 让变更过于容易，代码不断堆积而非重构）。作者最担忧的是可见性问题：不仅用户看不到内部，开发者也放弃了阅读代码。应对方面，作者看好非生成式 LLM 应用（如 bug 检测），并赞同「slopmeisters 与维护者军备竞赛」的思路——要求 LLM 生成的代码不能看起来像 LLM 写的，迫使生成者真正理解代码。作者反对 Foote 和 Yoder 认为泥球是「 cynical 最优解」的结论，主张 katamari 架构更糟，呼吁更小、更少的软件，由报酬更高、工作更少的开发者精心构建。

## 8. 警惕对隐喻的过度依赖：我们其实并不真正理解大脑

- 原始链接: <https://evnm.substack.com/p/beware-overreliance-on-metaphor>
- 英文标题: Beware overreliance on metaphor

本文作者Evan Meagher指出，隐喻是解释新概念的有效工具——例如用水压类比电压，帮助人借助已有经验理解陌生事物。然而，隐喻本质上是一种抽象，必然遮蔽信息，过度依赖会误导认知。作者以「意识只是大脑的计算」这一流行说法为例，批评将大脑等同于计算机的隐喻：神经元交换电信号与化学信号，现代计算机确实能模拟这一过程，但用「计算机」解释大脑近乎循环论证，是用地图代替了领土本身。作者进一步回顾历史：在计算机之前，人们曾把大脑视为电报网络，更早则视为钟表机械（笛卡尔在17世纪将部分脑功能类比为钟表与液压系统）。这一「用当下最新技术隐喻解释大脑」的序列令人谦卑——它既展示了科学与技术同步推进，也暗示当前「大脑即计算机」的断言可能和笛卡尔的机械论一样片面。作者的核心提醒是：隐喻能搭建理解的脚手架，但不应被当作对事物本质的完整描述，尤其在涉及大脑与意识这类尚未被充分理解的领域时，更应保持审慎。

## 9. agent-shell 0.78 版本更新

- 英文标题: agent-shell 0.78 updates

agent-shell 是一个 Emacs 原生模式，通过 ACP（Agent Client Protocol）与 AI agent 交互。0.78 版本新增 Antigravity（Google）和 Qoder CLI 两个 agent 后端。最核心的改进是持久化提示：缓冲区末尾始终保留可写提示，用户提交后提示立即返回，agent 处理期间新输入自动排队，显著降低认知负担。新增转向（steering）功能，允许在 agent 运行中修正方向而无需取消或等待，目前 Claude 和 Codex 支持该 ACP 扩展。RET 与 M-RET 的默认行为可通过变量配置，分别对应排队和转向。其他改进包括：支持从外部文件管理器拖放文件到缓冲区、会话头部显示累计 token 成本、折叠缓冲区搜索尊重 search-invisible、斜杠命令补全逻辑优化、新增复制最后输出命令、链接与表格渲染多项修复、视口分页支持前缀参数、会话列表分页、OpenCode 配置选项扩展等。同时新增 4 个第三方包，退役旧 Markdown overlay 渲染器。本月共 153 个提交、32 个 issue 关闭、25 个 PR 合并，项目由独立开发者维护，作者呼吁社区通过赞助和 GitHub star 给予支持。

## 11. 从虚无到可启动镜像：tine 构建系统

- 英文标题: From Thin Air to Bootable Images: The tine Build System

Amutable Systems 团队发布了基于 Buck2 引擎的开源构建系统 tine，目标是构建具有密码学可验证完整性的操作系统镜像。文章首先列出核心需求：最小主机依赖、完全锁定所有输入、集成包管理、廉价全量重建、可重现构建、原生镜像与 systemd sysext 构建、monorepo 快速迭代、Go/Rust 组件一等支持、SBOM 兼容及多级缓存。团队逐一评估了 mkosi（仅擅长单镜像、扩展性差）、Open Build Service（服务端过重、不灵活）、BuildStream（引导与扩展性不足）和 Antlir（过于绑定 Meta 内部场景），最终选定 Buck2 作为底层引擎，融合 Antlir 与 mkosi 的优点。tine 的核心概念是「box」——在 Buck2 的 Starlark 语言中原生声明的构建环境，类似容器但无需额外运行时，天然享受 Buck2 的哈希缓存与增量重建。文章以 Fedora Rawhide 为例，完整演示了从初始化仓库、定义 Go 构建环境、拉取 duf 项目、构建可启动磁盘镜像到在 QEMU 中自动登录运行的全流程。tine 还内置 CycloneDX SBOM 生成、PKCS#11 硬件密钥签名、依赖自动更新与目录刷新工具，并已支持 Arch 发行版。
