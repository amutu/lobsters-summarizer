## 1. Lingua Franca：任意语言中的直觉式并发编程

- 原始链接: <https://www.lf-lang.org/>
- 英文标题: Intuitive concurrent programming in any language

Lingua Franca 是一种反应器导向的协调语言，旨在帮助开发者构建可预测、确定性、时间敏感且分布式的并发系统。作为数十年计算模型研究的成果，它比线程、发布-订阅、Actor 及服务导向架构等框架提供更可重复的行为。其核心优势有三：一是确定性并发，消除线程管理、同步与竞态条件的顾虑；二是内置时间语义，使时间敏感任务无需复杂计时逻辑即可精确处理；三是简化分布式，开发者可几乎无修改地将单节点应用迁移至分布式架构。Lingua Franca 并非一门新编程语言，reactor 的功能体仍用开发者熟悉的语言编写，目前支持 C、C++、Python、TypeScript 和 Rust。文章以「石头剪刀布」为例，说明两个玩家同时出招在 Lingua Franca 中有精确语义，且其因果分析能自动检测因果环路并判定程序无效。该项目起源于加州大学伯克利分校，后由基尔大学、德累斯顿工业大学、达拉斯大学、挪威科技大学、汉阳大学及亚利桑那州立大学等机构共同推进，已开源并托管于 GitHub。

## 2. 九年破译Xbox 360：故障注入与DIY工具的胜利

- 原始链接: <https://kennedn.com/blog/posts/glitching/>
- 英文标题: It took me nine years to hack my Xbox 360

作者于2017年购入Matrix CoolRunner故障注入芯片，试图破解Xbox 360，但受限于工具与技能，项目搁置九年。文章解释了Xbox 360为何难以从软件层面攻破：一级引导加载程序（1BL）物理烧录于CPU硅片中，逐级验证微软签名，形成完整信任链。突破口在于故障注入——通过向CPU_RESET信号施加约100纳秒的脉冲，使CPU在执行「move register」指令时出错，将零值写入目标寄存器，从而绕过签名校验获得任意代码执行权。作者指出，随着硬件安全启动（如Windows 11的TPM要求、ESP32 v3、Nintendo Switch的PicoFly等）日益普及，故障注入已成为更主流的攻击向量；而5英镑的Raspberry Pi Pico凭借PIO模块约7.5纳秒的时序精度，让NAND转储和JTAG编程从耗时数十分钟简化为几秒完成，2026年作者轻松完成了2017年未竟之事。文章最后以讽刺笔调提到，纯软件漏洞恰在发布前一周曝光，使九年努力付诸东流，但这段深入硬件安全机制的探索本身极具价值。核心结论：安全体系越加固，故障注入越凸显；廉价DIY工具正将曾经高门槛的硬件攻击平民化。

## 3. PwnEscape：从Linux网络栈漏洞到KVM虚拟机逃逸（CVE-2026-99999）

- 原始链接: <https://pwn.ai/blog/pwnescape>
- 英文标题: PwnEscape: Guest-to-Host KVM Escape (CVE-2026-99999)

本文记录了研究者参与Vercel百万美元沙箱挑战后发现的Linux内核Critical级漏洞，该漏洞可实现从KVM虚拟机到宿主机的完整逃逸。核心缺陷位于Linux网络栈的校验和延迟计算（CHECKSUM_PARTIAL）机制：guest可控的sk_buff校验和元数据（csum_start与csum_offset）在L2/L3坐标归一化后未重新验证，导致skb_checksum_help()的延迟写入可覆盖kernel已解析的IPv4头部。具体而言，IPv4首字节的IHL字段可从0x45（20字节）被改写为0x4f（60字节），使后续ip_do_fragment()将原本28字节的线性数据误判为60字节头部，从而将32字节宿主机内存作为伪造的IP选项外发，形成可重复的宿主机内存泄露。在此基础上，研究者进一步利用分配器行为实现64字节内核写入，并在自有KVM环境中完成从泄露到宿主机root执行的完整利用链。该漏洞并非hypervisor自身缺陷，而是Linux网络栈的通用问题，影响多种虚拟化环境。上游修复补丁6785011f8b16通过在完成校验和前验证checksum_start位置来阻断攻击。研究过程使用了名为Omega-Pwn的自动化框架配合GPT-5.6 Sol进行源码分析，人类研究者负责方向把控与证据判定。Vercel将该报告评为其挑战项目最重要的发现，并协调了跨行业的披露与修复。

## 4. 废除AI！宣言

- 原始链接: <https://abolish-ai.net/abolish-ai-a-manifesto/>
- 英文标题: Abolish AI! Manifesto

「废除AI！宣言」是一份激进左翼政治宣言，主张将AI视为压迫性制度予以废除，而非作为中性工具加以改良。作者将废除AI类比废除奴隶制、监狱、警察等运动，强调其核心并非反对技术本身，而是追求一种解放性替代方案——即「从左翼发起的革命」以取代「全球技术法西斯主义」。宣言指出AI与资本主义不可分割，不存在「伦理AI」，也无法在资本主义框架内实现AI的废除。作者将AI界定为一种文化实践，即人类将思考外包给机器，并列举了AI在环境破坏、数据隐私、劳动异化、教育损害、心理健康及军事应用（如加沙冲突）等方面造成的广泛危害。宣言明确反对「缓解危害同时利用收益」的折中路线，呼吁行动者从个人层面（不再依赖AI代替思考、恢复规划与社交技能、寻找替代性活动）到集体层面（组织示威、罢工、直接行动、建立社区互助网络）展开实践，强调在去人性化的世界中拥抱真实的人类体验，以社区和团结为根基推动变革。

## 5. ActivityPub 单元测试的几点思考

- 原始链接: <https://shkspr.mobi/blog/2026/10/some-thoughts-on-unit-testing-activitypub/>
- 英文标题: Some quick thoughts on Unit Testing ActivityPub

作者 Edent 在 NLnet 资助的 ActivityBot 项目中，分享了自己为 ActivityPub 机器人框架编写单元测试的经验与难点。文章将测试分为四类：一是基本文本验证，例如校验 ActivityPub 用户名（如 @edent@mastodon.social），需处理国际化域名、Emoji 域名及用户名中允许的字符等，但相关规范分散且不易查找；二是消息验证，涉及 WebFinger 响应格式及各类 ActivityPub 消息的必填字段与取值范围，虽有 JSON Schema 可用，但规范同样零散；三是签名验证，HTTP Signatures 的验证与生成均存在困难，作者正收集真实签名样本供他人复用；四是跨服务器通信测试，发送签名请求尚可自动化，但接收外部消息需控制另一台服务器，难以完全自动化，且通过 Mastodon API 测试仅限公开服务器。作者最终将所有测试用例及消息、签名样本公开共享，希望为同类项目提供参考。文章核心观点是：ActivityPub 生态的规范碎片化是单元测试的主要障碍，而签名与跨服务器通信测试尤为棘手。

## 6. 交付你的解释器：用形式化证明验证 LLM 生成的语言语义

- 原始链接: <https://www.basis.ai/blog/ship-your-interpreters/>
- 英文标题: Ship Your Interpreter

本文介绍 Basis 团队的一项实验：让 LLM 为一种小型命令式语言（扩展 WHILE，解释器为 1855 行 C）编写形式语义，并在 Lean 证明助手中证明该语义与解释器编译为 RISC-V 机器码后的行为完全一致。文章指出，随着 LLM 在漏洞利用与验证两方面同步进步，可扩展软件验证的瓶颈已从定理证明转向规约本身——即如何确保所证明的语义确实反映程序真实行为。作者提出「交付你的解释器」这一思路：将已有解释器编译为 RISC-V 二进制，以之为基准，让 LLM 在 Lean 中证明语义与二进制对一切程序输出等价。实验中，证明过程暴露出语义的多处缺陷，如 64 位整数环绕、for 循环初始化器的异常处理、内置函数在打印与拼接中的不同渲染，以及函数名超过 63 字节时被 snprintf 截断等实现细节，这些均无法被测试套件覆盖。内存推理部分借助分离逻辑（移植 MachCSL 至 iris-lean）解决了 malloc 足迹随堆所有权变化的难题。最终证明从峰值约百万行 Lean 压缩至二十万行以内，不含额外公理，全部由 LLM 生成并经 Lean 机器检查。

## 7. 为调试而开发：Oxide 控制平面的 DNS 可观测性实践

- 原始链接: <https://www.davepacheco.net/blog/2025/developing-for-debugging-dns-propagation/>
- 英文标题: Developing for Debugging (2025)

Oxide 控制平面（内部代号 Omicron）运行外部与内部两套 DNS 服务，其权威数据存储在 CockroachDB 中，由核心组件 Nexus 在事件触发或定时周期内异步将配置传播至各 DNS 服务器，通常数秒完成。作者从「DNS 故障排查」这一经典痛点出发，梳理了传播链路中可能出错的每个环节：数据库数据错误、Nexus 未感知变更、服务器列表缺失、传播卡住、服务器返回错误数据等。由此催生了 omdb（Omicron 调试器），其核心抽象是「背景任务」——一组静态定义的异步 Rust 函数，可被事件或定时器激活，并返回结构化状态。omdb 无需深入了解 DNS 细节，即可输出包含配置版本、发现时间、各服务器传播结果与耗时的完整报告。文章提出「为调试而开发」的理念：在构建系统时即假设任何组件都可能异常，提前设计可采集的运行时信息。更进一步，软件应能给出肯定性证据（如「已将第 18 版配置于某时刻传播至三台服务器并全部成功」），而非仅报「0 问题」，从而让系统「自我证明清白」。此外，omdb 还可用于开发期测试、理解现有行为、新人教学及变更沟通，显著降低支持工单中的焦虑感，并可能因开发阶段即思考故障场景而减少运行时问题。

## 8. ORIB：回归经典 Reddit 界面并加入新增强功能的浏览器扩展

- 原始链接: <https://github.com/rajtilakjee/orib>
- 英文标题: orib: Bringing back the old Reddit interface, with a few new enhancements

ORIB 是一款基于 Manifest V3 的浏览器扩展，在 www.reddit.com 上将当前页面替换为经典 Reddit 布局，包括 subreddit 导航栏、蓝色页头、按热度排序的帖子列表、侧边栏及线程式评论。它通过 Reddit 的公共 JSON 接口读取列表数据，并借助用户现有会话完成投票、保存、隐藏、评论和提交等操作。扩展覆盖首页与 subreddit 的多种排序视图（hot、best、new、rising、controversial、top）、评论折叠与内联回复、用户资料页、经典提交表单、subreddit 侧边栏信息，以及自文本、图片、画廊和 Reddit 托管视频的展开预览。同时提供类似 Reddit Enhancement Suite 的键盘导航（j/k 切换、a/z 投票、s 保存、h 隐藏等），而 /chat、/settings、/poll、/mod、/message 等路径仍保留 Reddit 原生界面。安装方式为在 Chromium 浏览器中开启开发者模式并加载未打包的 extension 目录。商店提交版本为 0.1.0，通过 PowerShell 脚本打包为仅含 manifest.json、renderer.js、classic.css 和 icons 的 zip 文件。项目还包含架构文档、视觉设计规范、贡献指南及面向编码代理的说明，结构清晰，便于社区协作。

## 9. 锚定工程：让团队以AI代理速度交付软件的原则

- 原始链接: <https://nappingtoheavymetal.com/post/2026-09-15-principles-of-anchor-engineering/>
- 英文标题: Principles of Anchor Engineering

作者观察到，AI编码代理虽让单个工程师大幅提速，但团队整体并未同步加速，根源在于团队仍用为人类设计的流程来约束AI速度的开发，瓶颈在于共享理解、协调与方向一致性。为此，作者提出「锚定工程」（Anchor Engineering）方法，核心产物是与代码共存的「锚定手册」（Anchor Book），它将人类判断力编码为锚点，定义系统必须满足的约束，由AI代理据此生成代码。文章给出五条原则：一、AI放大而非替代专家判断，判断力决定产出质量；二、工程师拥有目标与结果，AI负责编写和维护代码，不再手工编辑；三、所有构建产物（设计、验证标准、工作分块）统一纳入锚定手册并版本控制，同一手册可切换实现语言；四、以「反摩擦」思路移除人为瓶颈，例如用里程碑跟踪替代任务分解，用AI自动化测试与变异测试替代团队代码审查；五、不牺牲理解深度，而是通过结构化锚定手册压缩建立系统心智模型的时间。作者强调，在AI时代，人类判断力仍是关键输入，团队应围绕锚定手册保持紧密协作，以接近代理速度交付高质量软件。
