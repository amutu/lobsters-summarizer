## 1. 《杜鹃之蛋：追踪计算机间谍》

- 原始链接: <https://en.wikipedia.org/wiki/The_Cuckoo%27s_Egg_(book)>
- 英文标题: The Cuckoo's Egg

《杜鹃之蛋》是天文学家Clifford Stoll于1989年出版的非虚构作品，记录了他追踪黑客Markus Hess的全过程。1986年，Stoll在加州劳伦斯伯克利国家实验室发现一笔75美分的计费异常，由此发现一名黑客利用GNU Emacs的movemail漏洞获取了系统超级用户权限。Stoll借来50台终端和电传打字机，在周末定位到入侵电话线，经Tymnet路由服务追踪至弗吉尼亚州MITRE国防承包商。此后十个月间，他通过日志分析、时区推断等手段，将入侵源锁定为西德。他设置了一个虚构的「SDI」部门作为蜜罐，成功诱使德国邮政定位到汉诺威的Hess住所。Hess长期将窃取的美军基地信息出售给苏联KGB。该书是最早记录的计算机入侵案例之一，Stoll也是首位以日志形式持续记录黑客行为的人。书中将「杜鹃蛋」这一鸟类寄生隐喻延伸至恶意软件领域，对网络安全术语产生了深远影响。此外，该书曾被改编为PBS纪录片《KGB、电脑与我》，书中提到的数列也成为著名的「Morris数列」数学谜题。

## 3. foldl 与 foldr 的本质区别：结合性、严格性与惰性求值

- 原始链接: <https://blog.haskell.org/foldl-and-foldr/>
- 英文标题: Differences between `foldl` and `foldr`

本文由 Alexis King 撰写，系统解释了 foldl 与 foldr 在严格语言和惰性语言中的行为差异。核心要点：两者并非「从左/右折叠」，而是结合性不同——foldl 左结合，foldr 右结合，遍历方向均为从左到右。在严格语言中，foldl 可尾递归、常数空间完成；foldr 需 n 个栈帧，为线性空间。在惰性语言（如 Haskell）中，情况反转：惰性 foldl 会逐层构建嵌套 thunk，反而退化为线性空间，因此应使用 foldl' 强制逐步求值以恢复常数空间；而惰性 foldr 在累加函数对第二个参数惰性时，可延迟计算、节省工作，甚至支持无限列表。文章给出实用准则：累加函数严格时用 foldl'，对第二参数惰性时用 foldr，切勿在列表上使用 foldl 或 foldr'。补充说明：上述结论仅针对 cons 列表（右结合结构）；对 snoc 列表则规则相反；对树等混合结构，推荐使用 foldMap 或 foldMap'，因其不预设结合性。

## 6. Turbo Haskell 编译器：在 JVM 上运行 Haskell 的 JIT 方案

- 原始链接: <https://comonad.com/reader/2026/turbo-haskell/>
- 英文标题: Turbo Haskell

Edward Kmett 在度假期间启动的 THC（Turbo Haskell 编译器）是一个基于 Truffle 与 GraalVM 的 Haskell JIT 编译器，运行于 JVM 之上。GHC 仍负责解析、类型检查、脱糖与 Core 优化，THC 接管后续编译与执行，已实现 GHC 9.14.1 全部 prim-ops，并完整支持 Template Haskell、Linear Haskell 及异步异常等高级特性。THC 同时支持 JIT 与 AOT（Native Image）两种模式，已能编译 pandoc、happy、alex 乃至 GHC 自身，并通过 Cabal 解析包、支持 Backpack 多库包。多语言 FFI 可调用 Python、Ruby、R、JavaScript 库，C/C++ 代码经 Sulong 执行。尾调用优化采用代码变换而非传统 trampoline，借助 64 位 Bloom 过滤器检测递归尾调用，将热路径压缩为紧凑循环；Data.Map 基准中快路径调用达数百万次而回退仅约 66 次。性能方面，预热后 Data.Map 等基准较 GHC 慢约 10%–20%，部分基准仍有 10 倍回退待优化。项目代码已开源，开发在 IRC 上进行。

## 7. 在 Rust 中实现 Arc 向下转型：PinRef 的设计与探索

- 原始链接: <https://wolfgirl.dev/blog/2026-09-29-pining-for-arc-downcasting-in-rust/>
- 英文标题: Pining for Arc Downcasting in Rust

作者在开发构建驱动时，发现并发缓存中对大型 JSON 值频繁调用 clone 开销巨大。将缓存值包装为 Arc<JSON> 后，clone 仅复制指针，代价大幅降低，但由此引出新问题：无法将 Arc<JSON> 向下转型为 Arc<String>，因为 Arc::deref() 产生的引用生命周期仅存在于当前作用域，无法安全地提取内部子指针。作者设计了一个名为 PinRef<V, T> 的结构体，内部持有 Pin<Arc<MustPin<V>>> 与一个 *const T 裸指针，借助 Pin 保证地址稳定性，使指针始终指向 val 内部有效位置。向下转型通过 project、filter_project、try_project 等方法实现，其核心思路是：若存在 for<'a> &'a T -> &'a U 的转换函数，则 *U 必为 *T 的固定偏移，从而可安全地将裸指针重新解释为 *const U。作者还讨论了为何不能用 &'static T 替代裸指针（移动会失效）、为何必须引入 PhantomPinned 防止 Unpin 破坏 Pin 保证等细节。最终方案实现了「拥有值但行为像引用」且支持向下转型的目标，但作者坦言实现中可能仍存在未发现的未定义行为，暂不确定是否发布为独立 crate。

## 9. Deser：重新思考 Rust 序列化

- 原始链接: <https://lucumr.pocoo.org/2026/9/29/deser/>
- 英文标题: Deser: Rethinking Rust Serialization

Armin Ronacher 介绍了他自 2022 年起开发的 Rust 序列化库 Deser，旨在解决 Serde 因设计约束而无法修复的长期痛点。文章列举了 Serde 的三个典型缺陷：任意精度数字与内部标签枚举冲突、flatten 导致整数键退化为字符串、适配器无法组合（如无法将 from_hex 套在 Option 内）。这些问题的根源在于 Serde 的三大设计决策：一套 trait 服务所有格式、固定数据模型在缓冲时丢失信息、以及调用栈递归。Deser 受 miniserde 启发，将架构反转为由格式向类型推送事件，嵌套状态存于堆上的 arena，从而消除栈溢出、支持可挂起解析、提供可扩展数据模型（扩展值替代带内信号）、无损缓冲及中间件层系统。此外还支持适配器组合、验证即适配器、derive 属性为 Rust 表达式、默认拒绝重复键、原生 flatten 等。在 XML 命名空间处理和 TOML 日期时间等场景下表现优于 Serde 生态。代价方面，JSON 读取平均慢约 10%，二进制体积明显增大，内部使用 unsafe，且无法替代 Serde 在生态中的统治地位。作者认为 Deser 目前至少可作为理论上的即插即用替代，其取舍对特定用户可能有利。

## 11. 用生成式测试发现正则引擎中的缺陷

- 原始链接: <https://matklad.github.io/2026/09/19/finding-bugs.html>
- 英文标题: Finding Bugs

本文以 Rust regex crate 中一个已知缺陷（正则「.abb|b」匹配输入「zabb」时错误返回「b」而非「zabb」）为案例，演示如何用极简 fuzzer 复现并发现更多 bug。作者的核心方法是「oracle 对比」：利用同 API 的 regex_lite 作为参照实现，随机生成正则表达式和输入字符串，逐一比对两者匹配结果，不一致即报告缺陷。生成策略上，作者强调不要追求大输入，而应聚焦短而精巧的样例：先随机选取字母表子集（swarm testing），再从中生成长度不超过 8 的字符串；正则生成则用权重分配给「或」「重复」「通配」「字面量」四种特性，递归构建并控制长度。搜索循环中，编译一次正则后跑 1000 个随机字符串以摊薄编译开销。作者指出，该 fuzzer 不仅复现了目标 bug，还额外发现了一个新缺陷，验证了方法的有效性。文章最后总结几条经验：构建 oracle 是生成式测试高效的关键；小而 tricky 的样例比大样本更易触发缺陷；即使最朴素的 PRNG 也足够危险；系统设计时应与测试工具协同设计（co-design）；这些技巧门槛不高，无需深厚理论背景即可上手。

## 12. 分支目标重用：JIT引擎中的Spectre-v2攻击

- 原始链接: <https://www.vusec.net/projects/btr/>
- 英文标题: Branch Target Reuse: Spectre-v2 Attacks in JIT Engines

本文提出了一种名为BTR（分支目标重用）的新型Spectre-v2攻击，针对浏览器、语言运行时及操作系统内核中的JIT引擎，影响Intel、AMD和Arm等多厂商CPU。其核心洞察在于：现代CPU在自修改代码后虽能恢复架构代码一致性，但未必清除陈旧的间接分支预测条目（BTB）。在JIT引擎中，这些陈旧目标可在新代码复用同一地址时被投机执行，形成「投机执行后释放」原语，使攻击者劫持投机控制流至过时偏移处的新代码，绕过软件加固或命中未对齐的gadgets。作者分析了Linux cBPF、Oracle GraalVM和Firefox的SpiderMonkey三处攻击面，并在Linux内核cBPF上构建了端到端利用，可绕过所有已启用缓解措施，以每秒约8字节的速率泄露任意内存（演示中成功提取root密码哈希）。此外，作者还首次将跳转偏移编码技术应用于cBPF，绕过了常量混淆加固。在SpiderMonkey中，利用WebAssembly字面量池可实现投机任意代码执行；在GraalVM中可投机跳过沙箱掩码操作，但GC活动会清除BTB条目，尚需进一步优化。Linux内核已上游IBPB刷新补丁（CVE-2026-64507/64508），Oracle通过随机化JIT缓存地址缓解，Mozilla则优先推进站点隔离。该论文已被CCS 2026接收。

## 13. 两种SQL查询构建器

- 原始链接: <https://mechanicalrabbit.github.io/FunSQL.jl/stable/two-kinds-of-sql-query-builders/#Two-Kinds-of-SQL-Query-Builders>
- 英文标题: Two Kinds of SQL Query Builders

文章指出，尽管SQL最初为人类设计，如今大部分SQL代码由程序生成，查询构建库因此成为刚需。作者将其分为两类：数据导向型（FunSQL、EF/LINQ、dbplyr）和语法导向型（Active Record、Laravel）。两者接口几乎相同，但原理根本不同：数据导向型将管道节点视为数据处理步骤，节点顺序影响输出；语法导向型采用构建器模式，将节点填入SQL语法树的固定槽位，顺序无关。语法导向型易实现、覆盖全，但继承了SQL刚性子句顺序等缺陷，难以组装复杂管道。数据导向型组装更直观，但需完整节点集合。EF/LINQ和dbplyr通过「SQL下推」从通用框架适配而来，无法覆盖SQL全部能力。FunSQL专为SQL从零设计，支持相关子查询、侧向连接、窗口函数、递归查询等完整特性，是唯一适合构建复杂数据处理管道的SQL查询构建器，且各节点具有明确的数据处理语义，未来有望发展为替代SQL的更连贯查询语言。

## 14. 从数据库消息队列到 Kafka：Tigris 的异步任务架构演进

Tigris 是一家对象存储公司，长期将 FoundationDB 作为唯一数据库，既存储租户元数据与跨区复制日志，也充当异步任务队列，其设计源自 Apple 为 CloudKit 开发的 QuiCK 系统。QuiCK 以时间为任务身份核心，任务键由队列版本、任务类型、命名空间、到期时间、优先级和随机 ID 组成；worker 通过扫描到期任务并「租约」方式领取工作，租约期间不断续期，崩溃后任务自动回退等待重试，从而在单库内实现持久化队列，避免双写问题。然而随着规模增长，调度产生的大量读写与用户请求竞争 FDB 资源，每个任务需多次写入，且自定义实现缺乏标准库、新人上手成本高。团队因此将垃圾回收等异步任务迁移至 Kafka，但保留 FDB 队列处理核心路径，并非一刀切替换。文章还讨论了基于 FDB 队列的固有缺陷：事务冲突、大规模积压时写入压力、时钟同步要求，以及随机领取任务可能导致部分任务长期饥饿。Tigris 在实践中做了多项改造：弃用 Record Layer、固定队列数量、为长任务增加 checkpoint、用自调度实现 cronjob，并改用密钥哈希分 lane 替代随机选取以缓解冲突与饥饿。文章以幽默笔调回顾了为何早期回避 Kafka（运维复杂、JVM 调优痛苦），最终承认引入 Kafka 是务实选择。

## 16. 唯一「直观」的界面是乳头：一句名言的溯源

本文追溯了「唯一直观的界面是乳头，之后一切都是学来的」这句在计算机交互领域广为流传的名言的出处与演变。该句通常被归于Bruce Ediger，也有人误以为是Steve Jobs所说，但2001年Bruce本人否认了原创性。作者RJK通过检索发现，引语词典中并无收录；最早可追溯到1994年8月Scott Francis在讨论中提出「乳头是唯一直观界面」的概念；1995年1月Jay Vollmer写出了接近最终版本的表述；同年2月至4月，Bruce Ediger多次在邮件列表中使用该说法的变体，其中4月的版本「基本上，唯一『直观』的界面是乳头，之后一切都是学来的」与流传最广的措辞高度吻合。文章指出，这句话的核心批判在于：人们频繁且不准确地将计算机用户界面描述为「直观的」，而事实上除婴儿吸吮乳头这类本能行为外，所有界面操作都是后天习得的。作者最终更偏好Bruce 2001年的修订版：「没有直观的界面，连乳头也不是，一切都是学来的」，认为这一表述更为彻底。

## 20. Aho-Corasick 多模式匹配算法

- 原始链接: <https://compiler.club/aho-corasick/>
- 英文标题: Aho-Corasick Algorithm

本文系统介绍了Aho-Corasick算法的构建过程，该算法用于在文本序列中同时匹配多个子串模式。文章首先回顾前缀树（Trie）的基本概念，即以n叉树形式存储字符串集合并共享公共前缀。核心部分讲解了两类内部链接：后缀链接与输出链接。后缀链接在转移失败时将当前状态回退到其字符串最长后缀所对应的节点（该后缀须为某模式的前缀），从而避免从头重新匹配；其构建采用广度优先遍历，逐层从父节点的后缀链接向上查找，根节点及其直接子节点的后缀链接均指向根。输出链接处理模式间的包含关系，例如匹配「spin」时需同时输出其后缀模式「pin」和「in」，其计算直接依赖已求出的后缀链接。文章给出了完整的伪代码，并说明最终需将带链接的Trie进一步转化为确定性有限自动机（DFA），使每次字符转移为常数时间，同时建议对稀疏转移使用稀疏矩阵存储。文章以「he」「she」「her」等示例演示了从Trie到DFA的完整转换过程，并推荐了原始论文作为延伸阅读。
