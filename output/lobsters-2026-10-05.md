## 1. Rust 的 derive 宏隐含 inline 属性及其对二进制体积的影响

- 原始链接: <https://yossarian.net/til/post/rust-s-derive-often-implies-inline/>
- 英文标题: Rust's derive often implies inline

本文指出 Rust 中 #[derive(Debug)]、#[derive(Clone)] 等派生宏在展开时会自动为生成的 trait 实现添加 #[inline] 属性。这一行为虽非语言规范硬性保证，但参考文档中的示例及宏展开结果均印证了这一点。对于字段简单的结构体，内联通常有益；但当错误类型形成深层嵌套层次（例如 ErrorA 含多个 String 字段，ErrorB 包裹 ErrorA，ErrorC 再包裹 ErrorB，外层枚举 Errors 又包含三者）时，每次调用 Debug 的 fmt 方法都会触发大量代码内联，在 debug/trace 日志等高频路径上尤为明显。作者以 uv 项目为例，发现通过编写自定义 proc macro（行为等同于 derive(Debug) 但标注 #[inline(never)]）阻止特定 Debug 实现的内联，可将二进制体积缩减约 160KB。作者认为 rustc 不对内联规模设上限在多数程序中是合理默认，但在错误层次极深、字段极多的真实项目中，开发者应有意识地控制内联策略以平衡性能与体积。

## 2. ncdu：基于 NCurses 的磁盘使用分析工具（Zig 重写分支）

- 原始链接: <https://github.com/rcalixte/ncdu>
- 英文标题: ncdu: NCurses Disk Usage (an updated fork)

ncdu-zig 是经典磁盘使用分析工具 ncdu 的 Zig 语言重写版本（2.x），原版为 C 语言实现（1.x）。ncdu 提供 ncurses 终端界面，主要用于在缺乏图形环境的远程服务器上快速定位占用大量磁盘空间的目录与文件，同时在普通桌面系统中同样实用。其设计目标是快速、简洁、易用，只需在任意安装了 ncurses 的最小 POSIX 类环境中即可运行。该 Zig 版本与 C 版本在实现和特性上存在差异，具体可参阅 ncdu 2 的发布公告。运行需求包括 Zig 0.17 编译器、POSIX 类操作系统、ncurses 库以及 libzstd 压缩库。安装方面，项目既支持 Zig 原生构建系统，也提供了传统 Makefile，用户可通过「make」编译、再执行「sudo make install PREFIX=/usr」完成安装，对不熟悉 Zig 构建流程的用户较为友好。总体而言，该项目为 ncdu 带来了更现代的编译语言实现，同时保留了原工具轻量、跨平台、适合终端环境的核心优势。

## 3. 几乎所有服务都应默认设置硬性预算上限

- 原始链接: <https://simonwillison.net/2026/Oct/3/default-hard-budget-caps/>
- 英文标题: We’re going to need default hard budget caps on pretty much everything

Simon Willison 在2026年10月3日的博客中呼吁，按用量付费的服务和API应默认启用「硬性预算上限」——即当月消费达到设定金额后直接停止服务并返回错误，而非仅发送警告邮件。他指出，编码代理和个人代理大幅降低了启动代码的门槛，但用户可能在睡眠中因失控服务产生数百甚至数千美元的意外费用，软性警告远不足以防范此类风险。他认为，企业和个人宁愿服务因超预算而报错，也不愿收到意外的一万美元账单；若用户确实想「冒险」运行无上限服务，应通过显式勾选确认来主动选择。文章提到，AWS已于2026年9月16日推出月度消费上限功能，项目达到上限后当月暂停；Google Cloud也在7月上线了类似的「Spend Caps」功能，表明这一趋势正在形成。Willison最希望AWS尽快将该功能推广至所有现有账户。他进一步展望，理想情况下AI代理应主动推荐具备硬性预算上限的提供商，并提醒新手避免部署使用无上限服务的应用，从而从源头降低财务风险。

## 4. grubby：用 Ruby 编写的 Git 仓库静态站点生成器

- 原始链接: <https://git.btxx.org/grubby>
- 英文标题: grubby: static site generator for git repos written in Ruby

grubby 是一个用 Ruby 编写的静态站点生成器，专为 Git 裸仓库设计，fork 自 RepoRat 并受其启发。运行环境要求 Git、Ruby 3.0+ 及 Kramdown。工具设计理念较为「opinionated」，开箱即用，默认以 Kramdown 解析 Markdown，并假设所有裸仓库以 .git 结尾，否则核心索引生成将失效。用户通常只需编辑 _config.yml 设置核心域名与路径，也可按需修改 style.css、_header.html、_footer.html 调整外观。默认在根目录输出 index.html 作为仓库索引。文章以共享主机（如 NearlyFreeSpeech.NET）为例，给出完整部署流程：将项目克隆至私有目录，在裸仓库 hooks 目录下创建 post-update 脚本并赋予执行权限，脚本通过临时克隆仓库后调用 grubby.rb 重建静态站点。生成后，各仓库站点输出到 /home/public/git.sitename.org/ 对应子目录，索引文件位于根目录。用户亦可将调用逻辑放入 post-receive 或全局 post-update 中，避免逐项目重复配置。需注意的局限是，grubby 不会为单个 commit、分支等生成独立页面。

## 5. true 的补码仍是 true——C++ 整数提升与布尔转换的陷阱

- 原始链接: <https://dryperspective.github.io/posts/complement-of-true/>
- 英文标题: The complement of true is true, except when it's false

本文围绕 C++ 标准提案 P4313R1（为 enum 添加位掩码操作）展开，深入剖析整数提升与布尔转换交互产生的反直觉行为。核心结论：由于整数提升，true 先变为 int 1，取补得 -2，再转回 bool 时因非零仍为 true，即「~true == true」。当 enum 底层类型为 bool 时，Clang 和 MSVC 遵循此规则，但 gcc 对 enum 类型采用截断最低位而非布尔转换，构成长期合规性缺陷。文章进一步指出，无固定底层类型的无作用域 enum 做位运算后转回原类型可能超出有效值范围，触发未定义行为；浮点数转 bool 型 enum 时，gcc 和 Clang 在特定优化级别下产生超出 [0,1] 的位模式，同样属于 UB。作者建议：在实现位掩码操作时排除 bool 底层类型，并通过自定义 concept 检测无固定底层类型的 enum 以规避 UB，同时计划向 P4313R1 作者反馈这些约束需求。

## 6. 改造 Go 编译器以高效实现 IPv4 到 IPv6 的映射

- 原始链接: <https://vincent.bernat.ch/en/blog/2026-go-netip-addrto6>
- 英文标题: Hacking the Go compiler to efficiently map IPv4 to IPv6

Go 标准库 netip.Addr 提供了 Unmap() 将 IPv4-mapped IPv6 地址还原为 IPv4，但缺少反向的 To6() 方法。维护者建议用户用 netip.AddrFrom16(ip.As16()) 替代，并期望编译器自行优化，但实测该写法比原生方法慢约 8 倍（7.14 ns vs 0.88 ns）。文章对比了三种实现：直接修改标准库（设置内部 z 字段为 z6noz）、外部 helper（即维护者推荐写法）、以及通过 unsafe 包操作内存布局的代理结构体。汇编分析显示，helper 写法因涉及 16 字节数组的打包、拷贝、解包而产生大量冗余指令，而标准库和 unsafe 方案仅需一次比较和一次赋值。作者进一步探索了修改 Go 编译器本身的两条路径：一是在 noding 阶段（IR 构建）将 AddrFrom16(As16()) 模式直接替换为结构体字面量，效果立竿见影但侵入性强、难以维护；二是在 generic SSA 阶段的 memcombine 优化 pass 中添加重写规则，消除「通过 Move 的 Load」等冗余内存操作，这是更合理的优化位置。文章详细展示了 SSA 形式中的值依赖链及三条重写规则的推导过程，为编译器优化提供了可操作的思路。

## 7. 仅用 OpenSSH 与 nginx 实现自托管 HTTP 隧道

- 原始链接: <https://vincent.bernat.ch/en/blog/2026-http-over-ssh>
- 英文标题: Self-hosted HTTP tunnels with SSH and nginx

本文介绍了一种不依赖 ngrok、frp 等第三方工具，仅凭 OpenSSH 和 nginx 即可搭建自托管 HTTP 隧道的方案。基本思路是：客户端执行「ssh -R 0:localhost:8080」将本地端口反向转发到远程服务器，nginx 通过正则匹配子域名中的端口号，将请求代理到对应本地端口，配合通配符 DNS 与 Let's Encrypt 证书即可对外提供 HTTPS 访问。为增强安全性，作者利用 nginx 的 ngx_http_secure_link_module，将 MD5 哈希与过期时间戳编码进 URL 的用户名字段（HTTP Basic Auth），哈希由过期时间、端口号和密钥共同计算，校验失败返回 401，过期返回 410，同时支持 WebSocket 代理。最大难点在于 OpenSSH 分配的临时端口不暴露于环境变量，作者编写了辅助脚本 http-over-ssh，通过遍历父进程链定位 sshd-session 进程，再用 ss 命令获取其监听端口，最终自动生成带 token 的完整 URL。用户只需在 ~/.ssh/config 中配置一条 RemoteCommand，执行单条命令即可获得可分享的隧道链接。方案的优势是零额外依赖、完全自托管，适合需要快速预览本地服务的场景。

## 8. Iroh 基于 BitTorrent Mainline 的全球内容发现方案

- 原始链接: <https://www.iroh.computer/blog/iroh-global-content-discovery>
- 英文标题: Iroh global content discovery

本文介绍 Iroh 项目如何利用 BitTorrent Mainline DHT 实现去中心化、无许可的全球内容发现。作者指出 IPFS 生态面临不确定性（shipyard 关闭），而 Mainline DHT 凭借极简设计（单 UDP 包、毫秒级查询、无持久化）在二十余年后仍是最可靠的公共 DHT。在传输层，Iroh 用 BLAKE3 验证流（iroh-blobs）替代 BitTorrent 的 SHA-1 分片机制，仅需一个根哈希即可校验任意数据段。由于 Mainline 仅存储 IPv4 host:port 而 Iroh 节点以 Ed25519 公钥（EndpointId）标识，作者设计了一个轻量 UDP 地址索引服务，将 host:port 映射到签名后的 EndpointId 记录，单台小服务器即可支撑百万级端点。在应用层，文章提出三层方案：一是通过 blake3.net 域名配合浏览器插件与本地网关实现内容寻址链接；二是引入 pkarr 去中心化命名系统（类似 IPNS），通过 pkarr.net 域名提供可变、可验证的名称解析；三是完整的发布-发现-下载工作流，包括 DHT 公告、地址索引查询、BLAKE3 校验下载。所有组件已实现于 iroh-content-discovery 实验仓库，并附有可运行的演示代码。

## 9. Thoreau BASIC 3.2 发布说明与项目介绍

- 原始链接: <https://thoreaubasic.com/>
- 英文标题: Thoreau BASIC

Thoreau BASIC 是一款源自 GW-BASIC 语法但全面现代化的 64 位 BASIC 解释器，具备 24 位图形、精灵、鼠标、TCP/IP、HTTP、复数/四元数/八元数运算、多核 PARFOR 并行及原生 x64 JIT 编译等能力。程序既可作为 Windows 应用运行，也可直接从 UEFI 固件启动而无需操作系统，并能打包为独立 EXE 或可启动 EFI 应用。3.2 版本将文件浏览器与菜单整合为普通 BASIC 命令（GETFILES、SELECTBOX），文件路径支持最长 4095 字节且保留原始大小写；新增 STATEWRITE/STATELOAD 双代检查点及分阶段保存与校验备份；引入 CRC32 校验、TEXTSTATS 文本统计和 SYSTEMINFO$ 系统信息报告；JIT 层面优化了浮点取整及复数、四元数、八元数运算。音频方面保留 Opus 音表及 WAV/FLAC/Opus/MIDI 播放，支持 NOGM 选项省略音表。项目附带示例 Pixel Prose，下载与项目页面托管于 itch.io，开发者通过 PayPal 接受支持，无强制弹窗或功能锁定。

## 10. 改进并稳定 NetBSD 中 racoon2 IKE 守护进程

- 原始链接: <https://blog.netbsd.org/tnf/entry/gsoc2026_racoon2>
- 英文标题: Improving and Stabilizing the racoon2 IKE Daemon in NetBSD

本文为 Google Summer of Code 2026 项目报告，作者 Artem Belan 在导师 Christos Zoulas 指导下，对 NetBSD 的 racoon2 IKE 守护进程进行了系统性改进。racoon2 是用于 IPsec 安全参数交换与安装的守护进程，包含 IKEv1/IKEv2 密钥交换、安全策略管理及 Kerberos 密钥交换组件。项目主要完成：按 RFC 7383 实现 IKE 分片收发；按 RFC 3947 在 IKEv1 Quick Mode 中构造与解析 NAT-OA 载荷；按 RFC 7296 §2.23.1 实现 NAT-T 传输模式地址替换，消除对额外选择器的依赖；统一配置中混乱的通配符地址宏；修复 IPv6 地址匹配与接口验证缺陷并默认启用；改进策略与提议协商逻辑以兼容 Windows、iOS、Android 等内置 VPN 客户端；建立无外部依赖的单元测试框架并新增四个测试程序覆盖 NAT-OA、地址替换、通配符及地址匹配逻辑。全部变更通过第 13 至 39 号拉取请求合并至 gsoc2026 分支，测试套件在 sanitizer 下 5/5 通过。剩余工作包括 racoon2ctl 控制工具、更多回归测试及端到端 IPv6 验证。

## 11. 为何我推荐 Renovate 而非其他依赖更新工具（2024）

- 原始链接: <https://www.jvt.me/posts/2024/04/12/use-renovate/>
- 英文标题: Why I recommend Renovate over any other dependency update tools (2024)

作者 Jamie Tanna 基于约五年使用 Renovate 并与 Dependabot、Snyk 对比的经验，系统阐述了 Renovate 的核心优势。首先，Renovate 提供数十项配置选项，且支持集中式可共享预设，团队可定义统一基线后各仓库仅用一行 extends 即可继承，避免了 Dependabot 需逐仓库手写 dependabot.yml 的繁琐。其次，Renovate 具备优秀的默认配置与自动生态系统检测能力，可通过 onboarding PR 降低接入门槛。在功能层面，Renovate 支持将多个包更新合并为单个 PR（如将所有 patch 更新归组），支持命令行一次性批量升级，覆盖 CircleCI、GitLab CI 等更多平台，并通过 custom managers（regexManagers）管理 Makefile 中的 curl 安装脚本、Dockerfile 中的 ARG 版本号乃至组织内部部署配置等非标准依赖。此外，Renovate 提供 Dependency Dashboard 总览依赖状态与待处理 PR，可配合 renovate-graph 等工具导出 SBOM。作者特别强调 Renovate 采用 AGPL3 开源协议，社区活跃、文档完善，而 Snyk 为专有软件，Dependabot 原为 source-available（2024年5月更新为 MIT）。无论自托管、使用 Mend 托管服务还是命令行调用，Renovate 都能满足工程团队对依赖更新的多样化需求。
