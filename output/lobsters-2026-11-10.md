## 1. 构建 Linux 发行版软件包到底消耗多少能源

- 原始链接: <https://www.wezm.net/v2/posts/2026/distro-energy-use/>
- 英文标题: How Much Energy Does Building Distro Packages Use

作者在为 Casuarina Linux 项目搭建构建服务器后，记录并分析了整个项目的能耗数据。构建服务器采用 AMD Ryzen 9 5950X（105W TDP）搭配 32GB DDR4 内存，放置在洗衣房并通过智能插座监控功耗。项目运行约 7 个月（2026 年 3 月至 11 月），累计完成约 5201 次包构建，总耗电 98.4 kWh，按 100% 可再生能源电价（AU$0.33/kWh）计算电费约 32.47 澳元，折合每月不到 5 澳元。作者仅在需要构建时手动开机，空闲时关机，有效避免了约 55W 的空闲功耗。最耗时的包为 Chromium，单次构建接近 4 小时，满载功耗约 193W，单次耗电约 0.77 kWh，成本约 25 澳分。作者指出，由于所有包先在桌面工作站（Ryzen 9 9950X3D，170W TDP，64GB DDR5）上预构建再推送至仓库，实际总能耗可能翻倍；此外家中装有屋顶太阳能，尽量安排在白天构建以利用光伏电力，进一步降低了实际成本，但无法精确量化。总体而言，维护一个小型 Linux 发行版的包构建在能源和费用上负担较轻，对普通个人开发者而言完全可接受。

## 2. 恶搞公钥：在RSA证书中藏入可读消息

- 原始链接: <https://maurycyz.com/projects/badcert/>
- 英文标题: Horrible public key tricks

作者对SSL/TLS证书体系表达不满：ACME流程繁琐、证书数月即过期、CA甚至使用密钥「4」这类弱参数。他提出一种「抗议证书」方案，既保留加密功能，又让公钥本身成为讽刺载体。核心技巧是在RSA模数n中嵌入可读文本：先取两个随机素数p、q算出n，再修改n的字节使base64编码中浮现一段吐槽文字（如「You don't actually have to pick random private keys」），随后将q调整为n/p附近的下一个素数。由于p与q量级相近，微调q仅影响乘积的低半部分，消息嵌入高半部分即可存活，通常不到四次尝试即可对齐base64分组。之后用certbot通过ACME让CA签名，得到一张功能正常、受信任的证书，续期时重复CSR流程即可自动化。作者也提到可针对浏览器base16视图嵌入更多文字。安全性方面，该操作确实降低了私钥熵，且q的取整可能使p、q过于接近从而可被分解，但作者指出脚本未做这些检查；不过现代TLS具备前向保密，即便私钥泄露，被动窃听仍需中间人攻击，对公开网站影响有限。文章附有生成脚本及多篇相关参考。

## 3. Microsoft 突然拒绝无 DMARC 记录的邮件

- 原始链接: <https://www.mythic-beasts.com/blog/2026/11/09/microsoft-are-rejecting-your-mail/>
- 英文标题: Microsoft are rejecting your mail

2026年11月9日，邮件服务商 pdw 发现 Microsoft 旗下邮件系统（含 hotmail.com 和 outlook.com）开始大规模拒绝入站邮件，返回「550 5.7.1 Message rejected: Message lacks SPF/DKIM/DMARC Auth Records」错误。经排查，受影响邮件的 SPF 与 DKIM 记录完全有效，唯一缺失的是 DMARC 记录；为相关域添加 p=none 策略后邮件即恢复正常投递。作者指出，发布 p=none 的 DMARC 记录在效果上等同于不发布，因此 Microsoft 此举相当于凭空新增一条无意义的入站限制，且完全未提前通知。相比之下，去年 Microsoft 曾提前公告要求日发送量超 5000 封的域必须配置 DMARC，而本次变更毫无预告，令人怀疑是否为有意为之。后续更新称该变更并非故意，但 Microsoft 尚未找到回滚方案。pdw 已为大量客户域紧急添加 p=none 记录，并呼吁受影响用户向 Microsoft 投诉，或考虑迁移至更积极处理邮件可达性问题的服务商。

## 6. 比 std::sort 更快的 C++ 快速排序：blqsort

- 原始链接: <https://tiki.li/blog/about_blqsort>
- 英文标题: A C++ Quicksort Faster Than std::sort

文章介绍了blqsort，一个在随机数据上比std::sort快约2倍的通用比较排序算法。其核心优化包括三方面：一是无分支分区，用条件增量指令替代条件跳转，避免分支预测失败导致的流水线冲刷；二是对不超过16个元素的小分区使用排序网络，以固定比较序列替代递归；三是稳健的枢轴选择，通过多中位数加随机性防止最坏情况，分布严重不均时回退到堆排序，并对大量重复键做专门优化。文章从基础递归快排讲起，逐步展示尾调用消除、随机枢轴、排序网络、无分支技巧等改进，并附汇编对比说明无分支版本的优势。blqsort以单头文件形式发布（MIT许可证），支持任意数据类型和用户自定义比较函数，另有C版本及多线程版本。基准测试在Apple M1和Intel i5-9300H上完成，排序5000万随机double时，blqsort分别耗时0.67秒和1.33秒，而std::sort为1.33秒和4.97秒；多线程版本在M1上还可再快约3倍。

- 原始链接: <https://nodejsdesignpatterns.com/blog/whats-new-in-nodejs-27/>

Node.js 27 于 2026 年 10 月以 Alpha 版本发布，首次采用新的年度发布节奏：10 月 Alpha、次年 4 月 Current、10 月晋升 LTS。核心亮点包括：V8 15.6 引入 Iterator.zip()、Iterator.zipKeyed()、Iterator.prototype.join() 与 includes() 等惰性迭代器方法，可逐对配对序列、将列数据转为命名对象、直接拼接字符串或短路搜索，全程无需中间数组；Math.sumPrecise() 采用高精度累加器，消除浮点求和漂移；node:net/promises 提供 listen() 与 connect() 辅助函数，net.Server 本身成为异步可迭代对象，大幅简化 TCP 服务器的 async/await 编写；虚拟文件系统 node:vfs 移除实验标志正式可用；核心模块升级涵盖 fs.mkstemp() 原子临时文件、权限模型新增 --allow-env、测试运行器支持稳定 watch 模式与 Jest 风格 mock、HTTP keepAliveTimeout 默认 65 秒。底层方面，V8 升至 15.6、OpenSSL 升至 4.1，8GB 机器默认堆上限提升至 4GB。破坏性变更涉及 req.headers 原型改为 null、多进程内存限制调整及 V8 序列化格式变化。文章建议生产环境暂不急于升级，等待 4 月 Current 版本。

## 11. S9：一种改进的插值样条曲线

- 原始链接: <https://gasiulis.name/new-spline/>
- 英文标题: Slightly better interpolating spline

作者介绍了其第九次尝试开发的插值样条曲线S9，旨在为交互式CAD应用提供自动平滑的曲线生成方案。文章首先论证了人类难以手动构造视觉良好的曲线序列，因为人眼无法感知多项式曲线曲率的细微变化，并借助密切圆和曲率变化图直观说明了「曲率变化越小、曲线越平滑」的规律。S9的核心目标是：易于形成圆形物体、最大曲率仅出现在节点附近、节点拖动时过渡平滑、每段最多一个拐点。在同类G2连续插值样条中，作者认为此前最佳方案为某单段三次曲线方案，其次为Adobe Illustrator采用的κ-Curves（二次曲线，求解器存在失败风险）和Hobby样条（不保证G2连续但求解简单），而Catmull-Rom等经典样条已不适合严肃CAD场景。S9采用基于Cesàro方程的非多项式曲线，以弧长为参数，通过两个权重参数控制曲率变化（权重为1时退化为Euler螺旋线），再配合全局求解器旋转各节点切线角度使相邻段曲率匹配。作者提供曲线与样条求解器的源码，但明确该实现不含直线到曲线的G2过渡、尖角或角度锁定等完整CAD功能。

## 12. 用树莓派与PPS GPS搭建微秒级精度NTP服务器

- 英文标题: Microsecond accurate NTP with a Raspberry Pi and PPS GPS(2021)

## 13. Sem86：无硬编码语义的x86全系统模拟器

- 原始链接: <https://liblisa.nl/sem86/>
- 英文标题: Sem86: a full-system x86 emulator without hardcoded semantics

Sem86是一款x86全系统模拟器，核心特点是运行时从外部文件加载指令语义而非硬编码，可灵活切换以精确模拟未定义行为和未文档化指令。虽使用LLVM而非定制JIT，性能仍达Bochs的1.9倍、QEMU的约42%，已在QRS'26会议发表。长期目标是与libLISA集成，利用自动推断语义实现「CPU克隆」；当前因libLISA尚缺16/32位x86观测器，仍用手写语义，但格式已高度兼容。在恶意软件分析中，Sem86支持执行中切换语义，可二分定位恶意代码利用未定义行为检测沙箱环境的具体指令。硬件方面，Sem86实现了Pentium 5时代所需硬件，可启动Windows 3.1/98/XP/7及Debian 8，可选配ES1370声卡、VBE高分视频和NE2k网卡。Android手机上亦可运行Windows 7，但低内存设备可能因JIT编译崩溃。Windows 98下可运行《过山车大亨》等游戏，XP下Firefox可访问HTTPS网站，但现代网站对早期CPU负载过重。

PyPI 完成了项目页面的重新设计并正式上线，旨在改善安全信号的呈现与包信息展示。随着 Python 生态快速增长，PyPI 面临更多恶意攻击威胁。2024 年引入的数字证明可验证发布文件来源，但多数用户对此不熟悉，旧界面也未能有效传达其含义。为此，PyPI 联合 Kabu Creative，依据 OpenSSF 证明样式指南对界面进行了改进。主要变化包括：新增「安全」标签页，集中展示发布文件的来源状态（完整来源或无来源）及逐文件证明；引入不完整来源、不一致来源、来源变更、来源丢失等多种警告机制，帮助用户识别账户劫持或流水线被篡改等风险；项目详情页将警告信息置顶，元数据按实用性重新排序并标注验证状态；发布文件与历史标签页支持搜索过滤、显示来源状态及延迟上传警告。此外，PyPI 扩展了用户文档，涵盖包安全评估、来源验证、完整性校验等内容。该项目由 Open Source Security Foundation 资助，相关设计模式已作为案例发布在 OpenSSF 证明样式指南中，供更广泛的开源生态参考。
