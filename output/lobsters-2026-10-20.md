## 2. 单哈希布隆过滤器

- 原始链接: <https://www.calabro.io/ohbf>
- 英文标题: One Hash Bloom Filters

布隆过滤器是一种概率型数据结构，能以极小内存开销快速判断某键是否属于某集合，返回「一定不在」或「可能在」。Bluesky后端广泛使用布隆过滤器，约99%的封禁、静音等查询可直接跳过数据库，大幅降低IO成本。传统方案需k个独立哈希，计算开销较大；双哈希方案用两个哈希推导k个位置，Bluesky曾采用该方案但受线程安全限制，mutex竞争使部署耗时90分钟，改用原子指令后降至15分钟。本文进一步介绍单哈希布隆过滤器（OHBF）：将位数组划分为k个两两互素大小的分区，仅一次哈希即得k个位位置。作者据此用Go实现gloom库，已在Bluesky后端及高性能同步服务jetstream中稳定运行近9个月。gloom还采用64字节块匹配CPU缓存行、缓存对齐、以MUL指令替代取模除法、分片原子过滤器等优化，确保最坏情况下仅一次缓存未命中，并有效减少多核间数据竞争。

## 3. A5 v1.0 发布：离散全球网格系统迎来稳定里程碑

- 原始链接: <https://a5geo.org/blog/2026/10/14/a5-v1>
- 英文标题: A5 v1.0

A5 是一个离散全球网格系统（DGGS），将地球上的任意位置、线或多边形区域表示为五边形单元格，每个单元格由紧凑的 64 位整数标识。经过 18 个月开发，A5 正式发布 v1.0，冻结网格布局与单元格 ID，确保应用、数据库和工作流可长期依赖。v1.0 带来多项重要改进：新增「covering」集合操作（并集、交集、差集、包含、重叠、计数、面积），支持在压缩数据上直接处理数十亿单元格；新增 cellToSubcells 与 cellToSupercell 空间层次函数；所有分辨率下单元格均为纯五边形拓扑，保证严格等面积，避免六边形 DGGS 中 12 个特殊五边形带来的偏差。底层核心改进是引入 teohedral 空间填充曲线，该曲线环绕全球且不自交，使多边形填充等操作可高效处理十亿级单元格，性能与 S2 相当，远优于 H3 在百万级即变慢的表现。生态方面，A5 已拥有 TypeScript、Rust、Python、DuckDB、R、QGIS 等实现，FIRMS Explorer 已用其聚合 6.31 亿条全球火灾检测数据。作者团队正撰写论文，将更严谨地阐述 A5 设计并与同类系统对比。

## 6. 为修复 0.000000000000000000542% 的除法边界情况而让所有除法变慢

- 原始链接: <https://futhark-lang.org/blog/2026-10-14-defining-division.html>
- 英文标题: Making all divisions slower to fix a bug in 0.000000000000000000542% of cases

Futhark 编译器通过生成 C 代码支持多种后端。由于 C 语言中 signed 整数溢出属于未定义行为，而 Futhark 的整数溢出是定义好的（回绕），这导致一个棘手问题：当 x 为 32 位最负整数（-2^31）且除数为 -1 时，x/-1 的结果无法用 signed 整数表示，触发未定义行为，在 x86 上甚至会引发 CPU 异常并崩溃。修复方案是在除法运行时函数中增加一个分支：若除数为 -1，则用 unsigned 算术取负；否则执行正常除法。性能代价方面，在 CPU 端（c 后端）由于分支极易预测，无可测量差异；但在 GPU 端（CUDA 后端），该分支导致循环展开后产生大量分支指令，性能从约 5.5 毫秒劣化至约 12.6 毫秒，接近 2.3 倍 slowdown；AMD GPU 上也有类似但稍轻的影响。作者承认这一代价令人遗憾，但正确性不可妥协，在常规基准测试中影响可忽略。对于确定不会出现负数的场景，用户可改用无符号除法以避免此开销。

## 7. Tor VPN Beta：从零构建 Android 原生 VPN 的实践经验

- 原始链接: <https://blog.torproject.org/tor-vpn-beta/>
- 英文标题: Tor VPN Beta: What we've learned building our own VPN for Android from scratch

Tor 项目团队于 2021 年提出 Tor VPN 构想，旨在将 Tor 的隐私保护从浏览器延伸至整个移动设备，2022 年秋季在 Android 平台有限发布 Beta 版。与商业 VPN 不同，Tor VPN 为每个应用分配独立 Tor 电路，实现应用级隔离以减少跨应用追踪，设计灵感源自 Tor Browser 的跨站追踪防护。上线后，核心使用场景迅速明确为「绕过网络审查」，尤其在伊朗、土库曼斯坦等高审查地区采用率显著高于 Tor Browser。团队由此调整优先级：在 1.4.0 版本中优先加入 WebTunnel 桥接，使 Tor 流量伪装为普通加密网页流量；修复桥接相关缺陷以提升可靠性。技术层面，应用基于 Rust 编写的下一代 Tor 实现 Arti 及 Onionmasq 构建，带来更少的崩溃和更稳健的网络处理；同时推进可复现构建并上架 F-Droid，降低对 Google Play 的依赖。团队也承认，出口选择功能曾导致用户误操作——试图绕过审查的用户错误地选择出口位置而非使用桥接，因此当前设计要求先连接 Tor 网络再选择出口。性能方面，Arti 尚未移植 C 实现中的拥塞控制等特性，仍是后续重点。项目由 The Guardian Project 和 LEAP 加密访问项目协作完成，团队将持续以开放方式迭代，聚焦审查规避、性能提升与用户体验优化。

## 8. Hanami 数据库层解析：Relations、Repos 与 Structs 的分工

- 原始链接: <https://aaronmallen.me/writing/hanami-why-model-citizens>
- 英文标题: Hanami, Why?: Model Citizens

本文是「Hanami, Why?」系列的数据库层专题，介绍 Hanami 区别于 Rails 传统 Model 层的设计。Hanami 的数据库层由三部分构成：Relations 定义表结构与关联（如 has_many、belongs_to），Repos 实现仓库模式以集中管理数据访问，Structs 作为冻结的对象表示承载展示逻辑。作者通过「Issue 新鲜度」示例说明仓库模式的核心价值：将查询语义收敛到单一文件，业务变更时只需修改 Repo 内部，调用方无需感知。另一关键优势是 Struct 为不可变对象，无法自行保存或懒加载，从而杜绝序列化器等组件意外写入数据库的问题。作者还分享了个人实践：将 Repo 拆分为只读的「*_queries」和含变更操作的「*_mutations」，并编写 RuboCop 规则强制跨切片仅导出只读部分。此外，文章坦诚指出从 ActiveRecord 转向 Sequel/ROM 存在学习曲线，如时间戳需手动扩展 ROM 的 Changeset 管道，但作者认为这恰恰体现了 Hanami 的高度可定制性。全文强调三者各司其职：Relations 描述数据、Repos 控制访问、Structs 安全传递，这一分离是 Hanami 数据层设计的核心哲学。

## 10. macOS 27.0 中神秘的 /pkg 目录到底是什么？

- 原始链接: <https://anderegg.ca/2026/10/18/what-the-heck-is-pkg>
- 英文标题: What the heck is /pkg?

作者在排查 PATH 环境变量问题时，发现 macOS 27.0 新增了 /pkg/env/global/bin 条目，由此展开调查。文章回顾了 macOS 自 10.5 起通过 path_helper 工具读取 /etc/paths 及 /etc/paths.d 下文件来构建 PATH 的机制，并梳理了历史沿革：10.15 为 rvictl 工具添加条目，13.3 为 Cryptexes 添加条目，而 27.0 则通过新文件 10-pmk-global 将 /pkg/env/global/bin 加入 PATH。据 Howard Oakley 的分析，/pkg 目录早在 26.4 的 Data 卷中就已出现，但直到 27.0 才被写入已签名系统卷的根目录，这一变化意义重大。该目录下包含 env、etc、inv、var 四个子目录，结合文件名中的「pmk」，社区猜测它可能是 Apple 即将推出的第一方包管理系统（「Package Management Kit」），但作者认为这与 Swift Package Index 等现有项目关联不大，且缺乏官方说明。文章的核心结论是：截至目前，包括 Apple 在内，无人能明确解释 /pkg 目录的用途，作者希望未来能获得更多信息，也提醒读者遇到该 PATH 条目时不必惊慌。

## 11. 让 dns_erlang 更快：BEAM 上的二进制优化技巧

- 原始链接: <https://blog.dnsimple.com/2026/10/making-dns-erlang-fast/>
- 英文标题: Making dns_erlang Fast: Binary Tricks for the BEAM

DNSimple 工程师 Nelson Vides 介绍了其开源 DNS 库 dns_erlang 的性能优化实践。该库运行在权威 DNS 服务器 erldns 上，每次查询需经两次解析（解码请求、编码响应），因此是热路径。团队在不使用 NIF 或 C 的前提下，仅靠理解 BEAM 二进制机制，将每查询 CPU 降低 12%、吞吐量提升 14%。文章归纳了五种模式：（1）编码时用单一累加器贯穿所有 section，避免中间二进制反复分配与拷贝；（2）解码时保持 match context，避免 Rest 逃逸到元组导致子二进制物化；（3）用函数子句匹配大块数据替代 rem 取模，规避 JIT 生成的 idiv 指令；（4）利用 SWAR（寄存器内 SIMD）技巧，在 BEAM 小整数 56 位限制内做并行字节检测，用于转义和大小写转换，该技巧随后被贡献至 OTP 29 和 Elixir 1.20 标准库；（5）为 DNS 压缩指针选择 VM 可廉价比较的 map 键，将 50 标签名编码从 211 µs 降至 9.4 µs。所有改动均通过 26434 条用例的字节级一致性验证。文章强调，阅读 JIT 生成的汇编（+JDdump true）是发现瓶颈最有效的手段。

## 18. 用超优化方法为 FPU 模拟器寻找最优位运算公式

- 原始链接: <https://purplesyringa.moe/blog/superoptimizing-an-fpu-emulator/>
- 英文标题: Superoptimizing an FPU emulator

作者在开发浮点计算库时，需要实现一个函数：给定 float 值 f，返回其二进制表示中最低有效位对应的数值。直接位操作实现需插入 if 分支判断是否为 2 的幂次，导致常见路径变慢且存在分支误预测风险。作者决定采用「超优化」思路——暴力枚举所有不超过 5 个操作的公式（操作包括整数加减、位与/或/异或、浮点减法、比较等），用少量代表性测试用例验证正确性。搜索采用归纳法逐层构建表达式，通过「相同输出只保留一个表达式」的去重策略大幅剪枝，整个搜索仅耗时 4 分钟。最终找到多个 5 操作公式，作者逐一手动检查后发现最后一个可通过子表达式复用压缩为 4 操作：关键洞察是 a - x.to_bits() 等价于 -(x & MANTISSA_MASK)，将取反与减法合并，节省一次运算。该公式对 2 的幂次会翻转符号位，但作者认为可接受。文章展示了不依赖 LLM、纯穷举搜索也能发现人类难以想到的巧妙改写，体现了超优化在小型无循环指令序列上的实用价值。

## 19. 零成本循环可变性的借用检查

- 原始链接: <https://antelang.org/blog/safe_cyclic_mutability/>
- 英文标题: Borrow Checking Zero-Cost Cyclic Mutability

本文介绍了Ante语言（一种基于所有权与借用语义的低级函数式语言）全新的借用检查设计。Ante的核心目标是比Rust更宽松地允许共享可变性，同时完全静态地杜绝悬空指针。新设计以「位置（places）」取代传统「生命周期（lifetimes）」，用精确的别名集合描述引用来源，并引入「不稳定位置（unstable place）」标记：对不稳定位置的变异只会使更深层的不稳定引用失效，而非所有同位置引用。这一机制使编译器能区分形状稳定（如元组内字段替换）与形状不稳定（如Vec清空导致内部指针重分配）的变异，从而在零运行时开销下安全放行大量Rust拒绝的合法代码。文章还展示了排他性通过Mutate效果在调用点检查、Use与Mention的区分、复杂数据流（如HashMap的get-or-insert）的自然支持，以及基于Rc共享指针的循环可变性（cyclic mutability）——用Rc构建环状结构后，编译器仅靠静态分析即可保证遍历与变异安全，无需任何运行时引用计数操作。新设计同时修复了旧版Distinct trait递归侵入私有字段、四种引用类型混淆等缺陷，并保留了线程安全。
