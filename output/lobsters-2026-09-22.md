## 1. 书评：《并行编程难吗？难的话怎么办？》

- 原始链接: <https://ahelwer.ca/post/2026-09-21-concurrency-textbook/>
- 英文标题: Textbook review: Is Parallel Programming Hard, And, If So, What Can You Do About It?

本文为Paul E. McKenney所著免费在线教材《Is Parallel Programming Hard, And, If So, What Can You Do About It?》的读者书评。作者长期从事TLA+与分布式系统研究，在2026年Software Should Work会议上受Filip Pizlo启发后开始系统学习并发编程，遂选择此书。阅读体验方面，教材提供三种PDF排版，但内部超链接过多，在电子阅读器上极易误触跳转，严重影响翻页体验。内容上，第3章讲解CPU缓存与硬件行为，但缺少MESI协议的基本介绍（仅附录提及），作者需自行补充；第4章详述编译器与CPU在并行程序中的「创造性」优化（如load tearing、store fusing、代码重排等），但视角偏Linux内核，对C11/C++11内存模型的讨论不足；第5章「计数」是全书核心，展示十余种多线程计数器实现，从原子操作的性能瓶颈到per-thread数组计数器及signal-theft limit counter，是理解伪共享等问题的绝佳载体。锁自由编程直到第14章才涉及，形式化验证章节使用Promela/Spin而非TLA+。作者虽仅深入阅读前五章，仍给予高度评价，认为该书成功激发了对并行编程的强烈兴趣，并计划下一步学习高性能垃圾回收。

## 2. 在 CGNAT 环境下实现家庭自托管

- 原始链接: <https://david.alvarezrosa.com/posts/self-hosting-behind-cgnat/>
- 英文标题: Self-Hosting Behind CGNAT

本文介绍在 IPv4 地址短缺导致运营商级 NAT（CGNAT）普及的背景下，如何绕过端口转发失效的问题，将家庭自托管服务暴露到公网。作者将服务部署在西班牙北部母亲家的地下室中，通过一台位于法国数据中心的廉价 VPS 作为桥接器，利用 WireGuard 隧道将全部流量转发至家庭服务器。由于隧道由家庭端主动发起，无需家庭侧拥有静态公网 IP。桥接器端通过 iptables 的 DNAT 规则将除 SSH（2222）和 VPN（51820）外的所有端口流量转发至家庭服务器，且仅改写目的地址，保留真实客户端 IP。家庭端配置路由表，使经由隧道进入的响应包回传至桥接器，而自身外发流量仍走家庭路由器，实现双向互通。代价是约 39 ms 的额外往返延迟。容错方面：家庭服务器用 cronjob 监控 SSH 可用性并自动重启；桥接器故障时可切换至 Cloudflare 隧道或 Tailscale 作为备用入口；隧道短暂断开会自动重握手。文章强调自托管带来的自由与独立性，鼓励读者摆脱对大型云服务商的依赖。

## 3. 你是否在链接上使用了 :visited 伪类？

- 原始链接: <https://kevquirk.com/do-you-use-visited-on-links>
- 英文标题: Do you use :visited on links?

作者讨论了CSS中「:visited」伪类在网页链接样式中的实际应用。长期以来，作者一直让已访问链接与未访问链接保持相同外观，这似乎也是大多数网站的默认做法，他从未深究。转折点来自他使用的RSS阅读器Miniflux——该阅读器正确利用了「:visited」，将已访问链接显示为紫色。由于作者通过RSS订阅了数百个博客，在阅读文章时能一眼辨别哪些链接已点击过，这一功能让他觉得非常实用。受此启发，作者决定在自己网站上启用「:visited」样式，将已访问链接设为紫色（#8839F7），未访问链接保持蓝色（#3995F7），效果微妙但足够明显。文章给出了极简的CSS代码示例，仅两行即可实现。作者还观察到，整个互联网上很少有网站使用「:visited」来区分链接状态，并就此向读者提问，引发对这一被忽视的CSS特性的关注。文章篇幅短小，属于个人博客上的轻量级技术随笔，核心观点是：「:visited」在信息密集的阅读场景（如RSS聚合）中具有实际价值，值得更多网站采用。

## 4. Rift：面向 macOS 的高性能平铺窗口管理器

- 原始链接: <https://github.com/acsandmann/rift/>
- 英文标题: rift - a tiling window manager for macos

Rift 是一款为 macOS 设计的平铺窗口管理器，以性能和易用性为核心目标。它支持多种布局风格，包括类似 i3/sway 的平铺、类似 bspwm 的二叉空间分割、浮动窗口、类似 dwm 的主-栈布局、类似 niri 的滚动列以及手风琴式栈布局。功能方面，Rift 提供菜单栏图标用于切换工作区、更改布局和快速控制；支持从菜单栏或命令行保存与恢复布局；焦点跟随鼠标并自动提升窗口；无需禁用 SIP 即可运行；具备流畅的窗口动画；支持触控板手势切换工作区；配置可热重载；通过 Mach 端口 IPC 与第三方程序（如 sketchybar）通信；并且兼容 macOS「Displays have separate Spaces」模式，这是其他主流窗口管理器所不具备的。项目起源于 glide-wm 的分支，但已大幅分化，底层依赖 yabai 等项目逆向工程的私有 API，作者认为私有 API 因系统本身构建于其上而更可靠、性能更优。作者开发 Rift 的动机是弥补 Aerospace 缺少动画及无法在单显示器全屏的同时操作另一显示器的不足。社区讨论在 Matrix 频道进行，作者也接受赞助支持。

## 7. Squalk：基于 Nostr 的老派论坛引擎（NIP-29 群组、NIP-7D 线程）

- 原始链接: <https://github.com/dtonon/squalk>
- 英文标题: Squalk: an old-school forum engine built on Nostr (NIP-29 groups, NIP-7D threads)

Squalk 是一个基于 Nostr 协议构建的论坛引擎，实现了 NIP-29（群组）与 NIP-7D（线程）规范，可管理小型或大型社区。它提供「简单」和「完整」两种模式：简单模式仅暴露单个论坛，完整模式可创建多个论坛，每个论坛右侧附带聊天侧边栏。技术栈方面，Squalk 需要一个支持 NIP-29 的个人中继和 Blossom 服务器（用于媒体上传），推荐方案为 Pyramid。配置完全通过 PUBLIC_ 前缀的环境变量完成，涵盖中继地址、模式选择、SSR 开关、缓存新鲜/过期窗口、搜索、标签、主题色等。内容定制依赖 NIP-23 长文事件（kind 30023），管理员可发布侧边栏资源链接和首页/联系页片段，内容以 Markdown 编写，仅论坛管理员发布的事件会被展示。构建基于 SvelteKit，支持两种部署目标：默认静态构建（单页包，任意 Web 服务器托管）和 SSR 构建（Node 应用，提供可爬取 HTML、JSON-LD、sitemap、真实 404 等）。部署通过 just 命令管理，静态模式 rsync 到远程主机并清除 Cloudflare 缓存；SSR 模式额外处理 systemd 服务重启，多实例通过不同 mode 和端口共存，要求 Node 22+ 及反向代理（如 Caddy）。

## 8. Markdown 应作为源代码纳入 /src 目录

- 原始链接: <https://htmx.org/essays/markdown-in-src/>
- 英文标题: Markdown in /src

蒙大拿州立大学教授 Carson Gross 在其咨询实践中观察到，随着 agentic coding 普及，LLM 生成的代码往往来自临时 prompt 会话，缺乏持久化的「源代码」，意图散落在 wiki、工单和 Slack 中。他提出：Markdown 正在从文档演变为真正的源代码，应被检查到 /src 目录中，与生成的代码并列。Markdown 具备纯文本可 diff、可 grep、可 review 的优势，LLM 原生读写，人类无需工具即可编辑，天然适合作为规格说明。作者建议在 /src 下新建 /src/md 目录，存放架构决策、数据模型、API 描述等接近规格说明的内容，并给出了 README、OVERVIEW、features、data、api、infrastructure 等子目录的约定结构。他强调局部性原则：代码模块旁即有解释其意图的 Markdown，消除「远距离规格说明」问题。测试仍保留在 /test 中，但应从 Markdown 派生而非从 prompt 派生。/src/md 应主要由人类编写和策划，agent 不应大量生成其中内容。作者承认该约定尚不成熟，但确信 Markdown 作为源代码的趋势不可逆，核心在于：代码生成变廉价后，意图本身成为最稀缺的资产，必须被持久化、版本化，供人与 agent 共同消费。

## 9. 关系代数（Relation Algebra）并非关系代数（Relational Algebra）

- 原始链接: <https://remy.wang/blog/ra-ra.html>
- 英文标题: Relation algebra is not relational algebra

本文旨在厘清两个仅差两个字母却含义迥异的概念：relation algebra（关系代数，属数学与逻辑学）与 relational algebra（关系代数，属数据库理论）。后者由 Codd 于 1970 年论文中引入、1972 年命名，是关系数据库的理论基石；其核心结果 Codd 定理表明它与域无关的关系演算（一阶逻辑查询的良性质片段）等价。前者则由 Tarski 等人以公理系统抽象定义，用于刻画二元关系上的代数结构；其对应定理指出 relation algebra 等价于限制最多三个变量的一阶逻辑 FOL³，但引入 fork 算子后可达到完整一阶逻辑的表达力。作者进一步指出，relation algebra 并非纯数学概念：Alloy 分析器（Z 记法的后继）即以它为基础；Dirk Van Gucht 团队也长期将其应用于数据库理论与系统；作者近期提出的 Prela 查询语言是继 IUGQL 之后首个基于 relation algebra 的查询语言。此外，Tarski 将 relation algebra 称为「the calculus of relations」（关系演算），这又与数据库中的 relational calculus 不同，造成三重混淆。为减少歧义，作者建议将其改称「Tarski 的关系代数」（TAR）。文章呼吁更多计算机从业者关注这一兼具内在美感与实用价值的代数体系。

## 11. 规划并跑通一条最优轨迹：天使岛实践

- 原始链接: <https://anishathalye.com/optimal-trace/>
- 英文标题: Running an Optimal Trace

「轨迹」（trace，旧称redlining）是一种跑步游戏，目标是在一次跑动中遍历某区域的全部小径。作者受朋友启发，为旧金山天使岛（19.4英里独特道路/小径）规划了一条最优路线，并开发了配套软件。文章详述了四个环节：一是侦察，综合OpenStreetMap、Strava/Garmin热度图、卫星图、街景及公园官方地图，确认小径是否存在及可通行性；二是选路，通过Overpass API拉取路网数据，在自建的Web界面中手动删除不可通行段、补全缺失段，并支持物理节点与逻辑节点两种编辑视图；三是优化，将问题建模为中国邮递员问题，用多项式算法求最小距离或最小爬升回路，时间优化则对应NP难的windy postman问题，最终作者选择最小化距离；四是跟跑，结合含高程的GPX导出（USGS 3DEP API）、Garmin手表实时导航、Organic Maps分段预览（每段4英里）等工具完成导航。最终规划路线23.8英里（含4.4英里重复段），实际跑完24.6英里，耗时约5小时。软件完全在浏览器端运行，代码已开源。

- 原始链接: <https://projectzero.google/2026/09/windows-dangling-com.html>

本文介绍 CVE-2026-66804 的利用方法，该漏洞是此前「Dark Elevator」（CVE-2026-50343）修复不完整所遗留的权限提升问题。根因在于 CrossDevice COM 对象（CLSID E9F83CF2-E0C0-4CA7-AF01-E90C70BEF496）在 HKEY_CLASSES_ROOT 下注册了全局可见的 CLSID 条目，但其服务器 DLL 路径指向 C:\ProgramData 下不存在的文件，而该目录所有用户均可写入，攻击者可植入任意 DLL。利用核心思路是借助自定义 COM 编组（Custom Marshaling）：实现 IMarshal 接口，在 GetUnmarshalClass 中返回悬空 CLSID，使目标进程在反编组时自动加载恶意 DLL。难点在于 Windows 8 起引入了 EOAC_NO_CUSTOM_MARSHAL 及 COMGLB_UNMARSHALING_POLICY_STRONG 等缓解机制，需寻找未启用这些保护的特权服务。作者最终锁定 Shell Create Object Handler（以 SYSTEM 运行、允许自定义编组），通过普通用户可触发的计划任务 CreateObjectTask 配合全局命名事件启动该服务，再经其 ICreateObject 接口将伪造编组对象传入，完成权限提升。文末还附有一段 PowerShell 脚本，借助 OleViewDotNet 和 NtObjectManager 模块扫描机器注册表中所有 LoadLibrary 无法加载的进程内 COM 类，帮助发现类似悬空注册。

## 16. tobi：跨设备保持命令在可分离会话中运行

- 原始链接: <https://tangled.org/ptr.pet/tobi>
- 英文标题: tobi: keep commands running in detachable sessions across your devices

tobi 是一个跨设备会话管理工具，允许用户在 Tailscale 网络中的多台设备上保持命令在可分离会话中持续运行。核心用法为「tobi -- nu」启动守护进程执行命令，关闭终端后会话自动分离，分离超过 24 小时则自动清理。用户可指定目标主机及用户名创建会话，也可通过会话 ID 直接创建。从网络中任意设备运行「tobi」命令会打开模糊选择器，列出所有主机的会话，支持回车登录、模糊搜索附加（如 tobi hx、tobi host.<TAB>）等多种方式。与 tmux 不同，tobi 不支持嵌套，在会话内运行 tobi 会直接替换为目标会话；多个查看器可同时附加到同一会话，此时采用最小终端尺寸。依赖方面，工具优先使用 tssh，回退到 ssh；Tailscale 仅用于服务发现。安装支持 nix flake 或 Go 编译，目标主机若未安装会自动部署到 ~/.local/bin 并支持版本升级。支持 Linux amd64/arm64 及 macOS arm64 平台。致谢提及 charm UI 库、Tailscale 及 LLM 辅助开发。
